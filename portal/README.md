# Портал «Лаборатория игр»

Онлайн-портал курса. Готовы ядро игр (этап 1) и каркас портала (этап 3, срезы 1–3).

- Срез 1: вход, урок по чекпоинтам, Фабрика с кубиками, продюсер, сборка игры ИИ с автопочинкой, мастерская правок, панель учителя, заметки автора и журнал генераций.
- Срез 2 «Играем вместе»: аркада класса и личная аркада, игра соседа с рекордом автора, вызов «побей мой мир» на зерне, плейтест тап-карточкой с открытием плейтеста по телеметрии, отзыв учителя.
- Срез 3 «Панель учителя и интерактивы»: проектор с кодом класса, таймером чекпоинта и тем, кто закончил шаг; живой урок с фильтром «застряли»; вау-старт на проекторе (карты урока 1 без спрятанной механики и простой вау-старт — шаг `teacher-demo`); квиз-раунды (шаг `rounds`); отчёт журнала генераций по моделям с CSV и сравнением моделей на одном замысле; расход лимитов и «+10 запросов»; статусы заметок автора и выгрузка в Markdown.

- Уроки в портале: 1, 2 и 4 (урок 4 «Глагол и основной цикл» с релизом модуля 1). Урок 3 ещё не собран.

Следующие шаги — в [docs/03_Промпты_следующих_шагов.md](../docs/03_Промпты_следующих_шагов.md).

## Запуск

Нужен Node.js 18 или новее, зависимостей нет.

```bash
node portal/server.js            # или: node portal/server.js 8090 — другой порт
```

Команду запускают из корня папки репозитория. На Windows проще двойной щелчок по `Запустить портал (Windows).bat` в корне: он сам переходит в свою папку. Ошибка `Cannot find module …\portal\server.js` значит, что консоль открыта в другой папке.

При первом запуске сервер создаёт `portal/config.json` и печатает пароль учителя. Адреса:

- `http://localhost:8080/` — вход ученика (код класса + ник) и учителя (пароль);
- `http://localhost:8080/teacher` — панель учителя;
- `http://localhost:8080/projector` — проектор учителя (кнопка «📽 Проектор» в панели открывает его для выбранного класса);
- `http://localhost:8080/arcade` — аркада класса для учеников (вход тем же кодом класса);
- ученики в той же сети открывают адрес, который сервер печатает в строке «Ученики в той же сети».

Без ключа портал работает в **демо-режиме**: продюсер проверяет только простые вещи, а вместо игры ученика собирается образец урока с его названием и решениями. Так можно пройти весь урок и проверить портал бесплатно.

### Подключить ИИ

Откройте `portal/config.json` и заполните:

```json
"ai": {
  "baseUrl": "https://api.provod.ai/v1",
  "apiKey": "ваш ключ provod.ai",
  "codeModel": "anthropic/claude-sonnet-5",
  "textModel": "anthropic/claude-sonnet-5"
}
```

Перезапустите портал. В панели учителя на вкладке «ИИ и расходы» кнопка «Проверить ключ и список моделей» покажет точные id моделей провайдера. Там же модели переключаются без перезапуска. Игры по API не пишутся: программист — Qwen в чате chat.qwen.ai (решение автора 18.10.2026). По API работают продюсер, связка карт и черновик отзыва, по умолчанию на Claude Sonnet 5 (`anthropic/claude-sonnet-5`); если `textModel` пуста, продюсер берёт модель из `codeModel`. Связку карт вау-старта пишет модель `codeModel`: связка — замысел для программиста, а быстрая текстовая модель давала несобираемые игры. Отдельную модель для связки можно задать ключом `"linkModel"` в `ai`. Sonnet 5 не принимает параметр `temperature`: портал не шлёт его моделям Claude, а для других моделей с таким ответом провайдера повторяет запрос без него.

Чтобы журнал считал рубли, впишите цены моделей в `models` (рубли за миллион токенов): `rubPer1MIn` — входящие, `rubPer1MOut` — исходящие, `rubPer1MCacheRead` и `rubPer1MCacheWrite` — чтение и запись кэша (без них кэш считается по цене входа). Цены в `config.example.json` — с provod.ai/ru/pricing на 17.10.2026; запись в кэш у Claude принята за 1,25 цены входа.

**Кэш промпта.** Системные промпты продюсера и связки одинаковы для всего класса на уроке. Повторное чтение из кэша у Claude Sonnet 5 стоит 16,75 ₽ за миллион вместо 167,52 ₽. Qwen, OpenAI, Gemini и DeepSeek кэшируют одинаковое начало запроса сами, Claude — только по метке `cache_control`, её ставит портал. Настройка `ai.cache`: `"auto"` (по умолчанию) — метка для моделей `claude-*`, `"on"` — для всех, `"off"` — без метки; поле `"cache": true/false` у модели в `models` важнее общей настройки. `ai.cacheTtl` — срок кэша, пусто — 5 минут, `"1h"` — час (запись дороже вдвое). Доля входа из кэша видна в панели учителя («ИИ и расходы» → «Все вызовы модели»), токены кэша — в CSV вызовов.

Ограничения в `limits`:

- `aiCallsPerStudentPerLesson` — запросов к ИИ на ученика за урок;
- `rublesPerLesson` — потолок расходов класса на урок, 0 — без потолка.

Оба лимита можно поменять и в панели учителя («ИИ и расходы» → «Лимиты»), без перезапуска: значения из панели лежат в `data/settings.json` поверх `config.json`. Отдельному ученику учитель добавляет запросы кнопкой «+10» в таблице урока.

## Как пройти урок самому (учитель + ученик)

1. Запустите портал и войдите учителем. Пароль — в `portal/config.json`.
2. Создайте класс, например «Прохождение автора». Слева появится код класса.
3. Откройте вход ученика в другом окне — удобнее в окне инкогнито — и войдите по коду с любым ником.
4. В панели учителя откройте первый чекпоинт. Ученик увидит его сразу, без перезагрузки.
5. Проходите шаги. Кнопка «Заметка автора» внизу слева сохраняет замечание к текущему шагу. Кнопка «Скопировать результат» в конце чекпоинта даёт текст для чата «Прохождение».
6. Вкладка учителя «Заметки автора» → «Скопировать все» — отправьте их в чат «Сборка», Claude превратит их в правки.

## Как устроен урок

Урок — файл `lessons/urok-NN.js`: цель, донор, линза, `plan` (в каких шагах лежит замысел), `feedback` (колоды понятий и вопросов для отзыва учителя), `wow` (вау-старт: колоды карт, колода спрятанных механик, запасная игра) и чекпоинты. Ещё три необязательных поля:

- `sample: { file, about }` — ремейк урока как образец механики: им отвечает подставной Qwen в демо-прогоне проверки портала;
- `demoForks` — развилки демо-продюсера под донора урока, чтобы без ключа продюсер не приносил волну пришельцев в чужую механику;
- `producer: { focus }` — что продюсеру проверить особо на этом уроке (дописывается к его системному промпту).
- `concepts` — три понятия урока (во всех 36 уроках). Карта открывается в боковой колонке после шага `after` и читается в три строки (Б1 аудита 21.10.2026): `formula` — бытовая формула крупно, `term` — термин мельче, пример. До сборки пример — `example` (донор), после — `own`: шаблон по замыслу ученика (`{title}`, `{twist}`… как в ИГРА, `{game}` — название игры для уроков без Фабрики), без вызова ИИ. Пустое поле замысла — снова пример донора. `title` и `text` — для листа урока и подсказок.

Продюсер (`producer`) стоит после ИГРА и до сборки во всех уроках с Фабрикой, кроме урока 1 (А3 аудита): шаг `{ id: 'prodyuser', type: 'producer' }` и `plan.producer`. Сборка его не ждёт.

Каждый чекпоинт — список шагов типовых видов. Отрисовка всех типов — в `public/student.js` (объект `STEPS`).

Игры модуля 4 объявляют уровни текстом: каждый уровень — карта из символов, у игры — легенда «символ → что это». Так одна и та же карта живёт в игре, в квизах, в редакторе уровней портала и в тепловой карте.

- Донор на оболочке: `lab.levels(список, легенда)` → уровни партии (свои или гостевые), `lab.level(i, карта?)` — начат уровень (карта — для сгенерированного), `lab.spot('death' | 'where' | 'secret', x, y)` — точка в клетках карты, `lab.clear({ moves, time })` — уровень пройден. Игра из чата делает то же через мост: `portal.levels`, `portal.level`, `portal.death`, `portal.where`, `portal.secret`, `portal.clear`.
- Гостевые уровни приходят в игру тремя путями: `?levels=` (base64url JSON `{ mode: 'only' | 'add', list: [{ name, map, author }] }`, так их ставят редактор и галерея), `lab.data.levels` и `window.__labGuest` — уровни гостей, которые автор принял в свою игру (сервер вставляет их в страницу игры).
- Телеметрия: `tele.spots` (`[вид d/w/s, x, y, уровень]`, до 420 точек) и `tele.maps` (`{ уровень: { name, map } }`); сервер собирает из них `discovery.heat` и `discovery.heatMine` для шага `heat`.
- API: `GET /api/levels?game=&code=`, `POST /api/levels` (уровень принимается, только если строитель его прошёл: `cleared`), `POST /api/levels/play`, `POST /api/levels/rate` (`like` или `rate` по трём вопросам), `POST /api/levels/accept` (автор кладёт уровень в свою игру, до 8). Уровни класса — `classes/<код>/levels.json`, код уровня — `L` и пять знаков. Событие SSE `levels`.
- Задание Qwen: поле урока `levels` дописывается в задание сборки разделом «Уровни как данные» (`ai/chat-prompt.md`, блок `chat:levels`); если в ответе нет `portal.levels(`, портал предупреждает.
- Шаги модуля 4 (`motion`, `order`, `mapquiz`, `heat`, `leveledit`, `gallery`) — в `public/steps-m4.js`, он подключается перед `student.js` и добавляет шаги в `STEPS`.
- Сцены объяснялок модуля 5 (уроки 19–22) — в `public/steps-m5.js` (после `steps-m7.js`, сцены добавляются в `window.LabMotion.MOTION`); новых типов шагов в модуле 5 нет, кроме квиза `clues` и вопроса `ask` плейтеста. Сквозные сценарии уроков — `tools/e2e-m5.js`.

Сервер модуля — `lib/m7.js`: арена в памяти, сетка и команды в классе. Шаг с `team: true` (замысел, решения, ИГРА в джеме) отдаёт ответ одного участника всей команде; игра команды одна на всех. ## Путь игры ученика

1. Фабрика, решения и ИГРА собираются в замысел (`buildPlan` в `server.js`).
2. Продюсер получает замысел и `ai/producer-prompt.md`, возвращает находки и развилки. Выбор ученика добавляется в задание программисту.
3. Портал собирает задание для Qwen из `ai/chat-prompt.md` (просьба автора, замысел, «Картинка», «Что нужно порталу»), ученик копирует его в chat.qwen.ai и вставляет ответ. Сервер достаёт код, проверяет синтаксис и, если ответ не подошёл, даёт сообщение для того же чата (до 3 ответов).
4. Игра открывается по адресу `/play/<игра>/<версия>`, в рамке `sandbox` с заголовком `CSP: sandbox`: код ИИ не видит данных портала даже в отдельной вкладке. Рекорды идут через `postMessage`.
5. Если игра упала, портал даёт сообщение для того же чата: ошибка со строкой и код (раздел `fix`). Каждая починка и правка — новая версия; все версии хранятся.
6. Каждый вызов модели записывается в `data/genlog.jsonl`. В записи — модель, время, токены, рубли, итог, игра и `build` — id сборки, к которой относится вызов. У версии игры — модель, попытки, время и рубли (`ms`, `rub`), `build` и отметка `ran`, когда она запустилась в рамке. Из этого складывается отчёт «с первой попытки» по моделям.

## Вау-старт и спрятанная механика игры класса

- **Карты при классе.** Вкладка учителя «Вау-старт»: учитель тянет пять карт из колод `wow.cards` урока (герой, действие, место, угроза, поворот). Карта с `parts: true` пишется «имя — особенность»: имя крупно, особенность строкой ниже (`Games.cardFace`), в квизе — `{heroName}` и `{heroTrait}`. Карта с `by: 'action'` и `decks` тянется из колоды, которая соответствует карте действия (в уроке 1 угроза и поворот берутся из колоды жанра, `lessons/urok-01-kolody.js`); перетянули действие — перетягиваются те такие карты, которых нет в колоде нового жанра (карта с тем же именем остаётся собой), а `wow.genres` даёт жанру каркас движка. У жанра с рецептом (пилот 19.10.2026: платформер, выживач, тир) в `wow.genres` ещё `recipe` — строки мини-игры, `types` — тип врага рецепта по карте угрозы и `rules` — что поворот меняет в рецепте; всё это уходит в связку и в задание Qwen, а колода героя этого жанра — имена с ручками жанра. Задания для прогона колоды до урока — `tools/pilot-zadaniya.js`. Карты сразу появляются у учеников в шаге `cards`, ученики голосуют «перетянуть». Перетянутая карта сбрасывает голоса.
- **Колода без повторов.** Карта не выпадает снова, пока класс не вытянет всю колоду, потом колода тасуется заново. Что уже выпало, хранится в классе (`wowSeen`), у `teacher-demo` — в состоянии вау-старта. В уроке 1 в колодах 32–40 карт, места частью адыгейские.
- **Спрятанная механика.** Кубик выбирает спрятанную механику из `wow.secrets` случайно, учитель видит её в блоке «Спрятанная механика игры» (по умолчанию скрыт — вкладку можно держать на проекторе) и может тайно заменить до сборки. Ученику урок отдаётся без колоды спрятанных механик.
- **Сборка.** «Собрать в Qwen» открывает окно Qwen с заданием из `ai/chat-prompt.md`: карты, гейм дизайн документ и спрятанная механика. Спрятанная механика живёт в ручке `secret` с пресетом «Без спрятанной механики» и в скрытом счётчике `portal.count('_secret')`. Сервер предупреждает учителя, если ручки или счётчика нет. Каждая сборка — новая версия общей игры класса.
- **Раздача.** Учитель проверяет игру во вкладке и нажимает «Раздать классу» — у учеников игра появляется в шагах `play` с `shared: true`. Пересборка забирает игру у класса до новой раздачи.
- **Чекпоинт 2.** Шаг `play` с `secretOff` выключает ручку спрятанной механики, шаг `secret` спрашивает догадку и только после неё раскрывает спрятанную механику (`/api/wow/guess`). Сводка во вкладке учителя: средний лучший счёт со спрятанной механикой и без, сколько раз сработала спрятанная механика, кто угадал и кто попался в ловушку карт.
- **Живые обновления.** Карты, голоса, сборка и раздача рассылают событие `wow`.
- **Наушники.** Флажок «В классе наушники» (`POST /api/teacher/wow/headphones`): без него звуковые спрятанные механики не выпадают ни на кубике учителя, ни в колоде спрятанных механик Фабрики.
- **Бот проверяет спрятанную механику.** Если бот-плейтестер не увидел ни одного срабатывания `_secret`, отчёт получает находку `SECRET_SILENT`, а панель один раз сама отправляет игру программисту на исправление (`playtest-fix` с `auto: true`).

## Играем вместе (срез 2)

- **Аркада класса** — `/arcade` для учеников и вкладка «Аркада» у учителя. Каждая собранная игра попадает туда сама, с первой версии. На карточке:
  - название и автор-ник, подпись «по мотивам механики …»;
  - «Что решил я» — три решения ученика;
  - текущая версия и рекорд класса.

  Автор скрывает игру из аркады в «Моих играх»: у одноклассников она пропадает, у автора и учителя остаётся.
- **Личная аркада** — «Мои игры» на `/arcade`: игры по урокам, версии, партии чужих игроков и открытие плейтеста.
- **Рекорды.** Таблица рекордов игры — `scores/<класс>:game:<id>`. Рекорд автора — его лучший счёт в своей игре.
- **Вызов «побей мой мир».** После партии портал выдаёт код из 6 знаков и ссылку `/arcade?ch=КОД`. В вызове записаны игра, версия, зерно и счёт.
  - Принявший вызов играет в `/play/<игра>/<версия>?seed=<зерно>`: оболочка читает зерно из адреса и строит тот же мир.
  - У вызова своя таблица.
  - Если вход не выполнен, ссылка ведёт на вход и после него обратно в аркаду.
- **Телеметрия для автора.** Партия чужого игрока в игре ученика пишется в `games/<id>/plays.jsonl`: счёт, версия, зерно и `tele` из сообщения `over` (`hold`, `presses`, `custom`). Туда же идут нажатия «ещё раз» (сообщение `again`) и карточки плейтеста.
- **Открытие плейтеста** считается только по чужим партиям:
  - сколько партий сыграли и сколько было игроков;
  - сколько раз нажали «ещё раз»;
  - какую кнопку держали дольше всего и какую долю времени. От 50% — «похоже на доминирующую стратегию»;
  - эмоции и карточки соседей.
- **Отзыв учителя** — в карточке ученика в панели: одно понятие геймдизайна и один вопрос, с кубиками из `feedback` урока. Ученик видит отзыв сразу, в шаге `playtest`.
- **Черновик отзыва** — кнопка «🪄 Черновик» у отзыва (`POST /api/teacher/feedback/draft`): ИИ по ответам и игре ученика предлагает понятие, вопрос и почему (`ai/feedback-prompt.md`, ответ JSON), без ключа — черновик по правилам. Отправляет учитель сам.
- **Живые обновления.** Новая версия игры, чужая партия и карточка плейтеста рассылают событие `arcade`, отзыв учителя — `feedback`. Шаги `arcade` и `playtest` и страница аркады обновляются без перезагрузки.

    сверху два чипа: «🤡 Провал урока» и «🖼 Галерея и нарезка» (Д5 аудита): стена провалов класса (`GET /api/teacher/fails`) — заметка, причины, «что поняли», голоса «😂 самый смешной»; режим «🎬 Нарезка лучших» — пять самых смешных по голосам по одному в рамке, «Дальше →».   - вкладка «🎯 Цель» (Д2 аудита) — цель класса: «партий в игры друг друга» (5–100 000) и награда: секретный донор «Звездопад над Фиштом» (`games/zvezdopad.js`, его нет ни в одном уроке), «Арена класса» раньше урока 26 или свой приз словами. Считаются только партии в чужие игры (`/api/score` не от автора и не от его команды), счётчик крупно на проекторе, строкой на вкладке «Урок», полосой у учеников над доской и в аркаде. Цель взята — конфетти и «▶ Играть» у всех. `GET /api/goal`, `POST /api/teacher/goal` (`target`, `reward`, `text`, `reset`, `off`), событие `goal`;
  - живые реакции (Д3 аудита): пока на проекторе видна игра в рамке (Провал дня, турнир, Фестиваль, вау-старт), у учеников внизу кнопки 😂 😮 🔥 👏 😱 ❤️ с её названием. Эмодзи всплывают поверх рамки на проекторе (не больше 30 разом), в углу — счёт. Частота: ученик — не чаще раза в 0,7 с и 12 за 10 с, класс — 20 в секунду. Проектор раз в 5 секунд пишет реакции в телеметрию игры (секунда партии и эмодзи), в открытии плейтеста автора — «Где смеялись» по пятисекундным отрезкам. `POST /api/teacher/live`, `POST /api/react`, `POST /api/teacher/react/log`, события `live` и `react`;
  - заставка чекпоинта (Д7 аудита): учитель открыл новый чекпоинт — у учеников и на проекторе на секунду титр «Уровень N: название» и минуты со звуком; поверх кликов не встаёт, при «уменьшить движение» — без анимации;
  - проектор слушает события класса (`/api/events?token=…&code=…`): реакции, театр, цель и галерея приходят сразу, а не опросом раз в 2 секунды.
  Код: сервер — `lib/klass.js`, ученик и аркада — `public/klass.js` (`LabKlass`: `splash`, `goalBar`, `reacts`, `teatr`, `fails`), проектор — `public/klass-pult.js` (`LabKlassPult`). Проверка — `tools/e2e-klass.js`.
  - вкладка «🎠 Карусель» (Г5 аудита, только в уроке с шагом `karusel`, урок 10) — большие часы круга, кольцо мест и кто уже отправил отзыв; «▶ Запустить карусель» (нужны хотя бы две собранные игры урока), «⏭ Следующий круг сейчас» (если все уже сыграли), «■ Закончить», потом «↻ Новая карусель» или «Убрать». Смена круга — звук на проекторе и у учеников. Код — `public/steps-m3.js` (`LabStepsM3.karuselPult`), сервер — `lib/karusel.js`;
  - вкладка «Выставка и турнир» — только в уроке с шагом `vote` (урок 8): лидеры трёх номинаций и сколько учеников проголосовало, а под ними — кнопочный турнир в игре-победителе номинации `tournament`. Ученики выходят по одному: учитель вписывает имя, партия попадает в таблицу турнира, лучший счёт наверху. Рамка игры и таблица не сбрасываются при обновлении проектора.
- **Живой урок** во вкладке «Урок»: у открытого чекпоинта — таймер и «закончили: N из M». По каждому ученику:
  - на связи ли он (открыта страница урока или аркады);
  - шаг, где он сейчас, и сколько открытых шагов осталось;
  - «своими словами»: сколько полей во всех ответах урока заполнено и сколько оставлено кубику. От трёх полей кубика ячейка подсвечивается;
  - игра: версии, текущая ошибка и сколько версий падали;
  - запросы к ИИ: «12 из 40», полоска расхода и кнопка «+10»;
  - движение: когда ученик последний раз сохранял ответ или звал ИИ.

  Фильтры: все, «застряли» (нет движения 5+ минут, а в открытых чекпоинтах есть недоделанные шаги — строка красная), «кубик 3+», «ошибка игры», «лимит ИИ на исходе». Сверху — расход ИИ на урок класса: рубли, вызовы и потолок.
- **Вау-старт на проекторе.** Вкладка «Вау-старт» проектора работает с обоими видами вау-старта:
  - урок с колодой `wow` (урок 1, раздел «Вау-старт и спрятанная механика игры класса» выше): крупно все карты колоды, голоса «перетянуть», «🎲 Тянуть карту» (пробел), «⚙ Собрать игру с ИИ» (Enter), проверка игры и «📣 Раздать классу». Спрятанная механика на проектор не выводится: её видит и меняет только панель учителя;
  - урок с шагом `teacher-demo` — простой вау-старт без спрятанной механики, описан ниже.
- **Шаг `teacher-demo`** (проверяется уроком-проверкой `tools/fixtures/lessons/urok-90.js`):
  1. Учитель тянет три карты колоды безумных идей пробелом или кнопкой: герой, место, поворот. Карта крутится барабаном. Кубик у карты перетягивает её, кубик у названия — название из колоды `names`, название можно и вписать.
  2. С первой карты идёт обратный отсчёт `minutes` (5 минут). Ученики видят «Смотри на проектор», те же карты и отсчёт вживую.
  3. «⚙ Собрать игру с ИИ» (Enter): замысел «Space Invaders × поворот × мир» собирается из шаблонов `plan` шага. Игра запускается на проекторе. Если упала — программист чинит её сам, до 2 попыток.
  4. Игра открывается у всех, когда выйдет время, или раньше — кнопкой «▶ Открыть всем сейчас». «⏸ Скрыть от учеников» держит её закрытой. Ученики играют в рамке, рекорды — общая таблица класса по этой игре.

  Игра учителя хранится отдельно для каждого урока класса (`classes/<код>/demo-<урок>.json`), в аркаду класса не попадает. «↺ Новые карты» начинает вау-старт заново.
- **Отчёт журнала генераций** («ИИ и расходы») — проверка главного допущения. Одна строка — одна собранная игра: сборка ученика, вау-старт или сравнение, вместе с её починками. По каждой модели:
  - доля игр, заработавших с первой попытки: сборка без починки синтаксиса, игра запустилась в рамке (сообщение `ready`) и не упала. Доля считается по играм, которые хоть раз запускались;
  - доля игр, которые работают в итоге, после починок;
  - среднее число починок (синтаксиса на сервере и ошибок в рамке), среднее время и рубли на одну игру;
  - сколько игр ещё не запускали и сколько сборок не дали игры вовсе.

  Кнопки «⬇ CSV по играм» и «⬇ CSV всех вызовов» выгружают таблицы для Excel: разделитель «;», UTF-8 с BOM. Демо-сборки в отчёт не входят.
- **Сравнение моделей на одном замысле.** В карточке ученика — «⚖ Пересобрать другой моделью». Замысел, по которому ученик собирал игру, сохранён в игре (`plan`); его пишет выбранная модель, она же чинит свои ошибки. Пересборка — отдельная игра учителя (`compareOf`), её нет у ученика и в аркаде. Версии A (ученик) и B, C… (учитель) открываются в одной рамке по очереди. В отчёте сравнения стоят рядом.
- **Лимиты.** Расход урока класса и «12 из 40» по ученикам видны в панели. «+10» и «+5» добавляют ученику запросов на этот урок (`aiBonus`), ученик сразу получает уведомление. Общие лимиты правятся во вкладке «ИИ и расходы».
- **Заметки автора со статусом:** новая, в работе, сделано. Фильтр по статусу, «⧉ Скопировать» в Markdown и «⬇ Markdown» — файл, сгруппированный по статусам, с чек-боксами `- [ ]` и `- [x]`. Статусы лежат в `data/notes-status.json`, сами заметки не меняются.

## Проверки

```bash
node portal/tools/check.js                # после задачи: только то, что задели изменённые файлы (--dry — план, --full — всё)

```

`e2e-portal.js` делает два прогона. Первый — с подставным ИИ (`tools/mock-ai.js`):

- продюсер отвечает развилкой;
- первая сборка нарочно падает, и проверка ждёт автопочинку;
- правка даёт новую версию;
- «Играем вместе»: второй ученик собирает игру, ученики играют в игры друг друга, бьют рекорд автора с зажатой клавишей, бросают и принимают вызов на зерне, оставляют плейтест;
- открытие плейтеста видит «→» доминирующей кнопкой, учитель пишет отзыв, и ученик видит его без перезагрузки;
- аркада класса, личная аркада и скрытие игры;
- срез 3: проектор (код, таймер, кто закончил шаги, карты вау-старта урока 1 без спрятанной механики), сравнение моделей (`mock-alt` собирает без ошибок), фильтр «застряли», «+10 запросов», расход урока, статус заметки и Markdown, отчёт по моделям и оба CSV.

В конце каждого прогона учитель переключает класс на урок-проверку `tools/fixtures/lessons/urok-90.js`: вау-старт `teacher-demo` на проекторе (карты пробелом, ученик видит их вживую, сборка при всех, автопочинка упавшей игры, «открыть всем», ученик играет).

## Безопасность

- Ключ API и пароль учителя хранятся только в `config.json` на сервере. Данные учеников — только в `data/`. Ни то ни другое не попадает в git.
- Ученики входят по коду класса и нику, без фамилий и других личных данных.
- Игры работают в изолированной рамке без доступа к порталу. На хостинге их нужно отдать с отдельного домена (этап 5).
