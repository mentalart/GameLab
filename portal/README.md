# Портал «Лаборатория игр»

Онлайн-портал курса. Готовы ядро игр (этап 1) и срезы 1–2 каркаса портала.

- Срез 1: вход, урок по чекпоинтам, Фабрика с кубиками, продюсер, сборка игры ИИ с автопочинкой, мастерская правок, панель учителя, заметки автора и журнал генераций.
- Срез 2 «Играем вместе»: аркада класса и личная аркада, игра соседа с рекордом автора, вызов «побей мой мир» на зерне, плейтест тап-карточкой с открытием плейтеста по телеметрии, отзыв учителя.

Срез 3 (интерактивы и панель учителя полностью) — в [docs/03_Промпты_следующих_шагов.md](../docs/03_Промпты_следующих_шагов.md).

```

  lessons/      сценарии уроков: urok-01.js — чекпоинты из типовых шагов, колоды кубиков
  public/       страницы: вход, урок ученика (student.js — все типы шагов), аркада класса (arcade.js), панель учителя;

  engine/       движок игр: Babylon.js 9.31.0 + Havok в vendor/, оболочка «Лаб3D» (lab.js), страница игры
  games/        ремейки-доноры учителя: образцы механик для уроков и для ИИ
  ai/           промпты: программист игр (game-prompt.md), продюсер (producer-prompt.md)

```

## Запуск

Нужен Node.js 18 или новее, зависимостей нет.

```bash
node portal/server.js            # или: node portal/server.js 8090 — другой порт
```

При первом запуске сервер создаёт `portal/config.json` и печатает пароль учителя. Адреса:

- `http://localhost:8080/` — вход ученика (код класса + ник) и учителя (пароль);
- `http://localhost:8080/teacher` — панель учителя;
- `http://localhost:8080/arcade` — аркада класса для учеников (вход тем же кодом класса);
- ученики в той же сети открывают адрес, который сервер печатает в строке «Ученики в той же сети».

Без ключа портал работает в **демо-режиме**: продюсер проверяет только простые вещи, а вместо игры ученика собирается образец урока с его названием и решениями. Так можно пройти весь урок и проверить портал бесплатно.

### Подключить ИИ

Откройте `portal/config.json` и заполните:

```json
"ai": {
  "baseUrl": "https://api.provod.ai/v1",
  "apiKey": "ваш ключ provod.ai",
  "codeModel": "qwen3.7-max",
  "textModel": "qwen3.8-flash"
}
```

Перезапустите портал. В панели учителя на вкладке «ИИ и расходы» кнопка «Проверить ключ и список моделей» покажет точные id моделей провайдера. Там же модель программиста и продюсера переключается без перезапуска: например, Qwen или Claude Sonnet 5 для игр.

Чтобы журнал считал рубли, впишите цены моделей в `models` (рубли за миллион токенов): `rubPer1MIn` — входящие, `rubPer1MOut` — исходящие. Ограничения в `limits`:

- `aiCallsPerStudentPerLesson` — запросов к ИИ на ученика за урок;
- `rublesPerLesson` — потолок расходов класса на урок, 0 — без потолка.

## Как пройти урок самому (учитель + ученик)

1. Запустите портал и войдите учителем. Пароль — в `portal/config.json`.
2. Создайте класс, например «Прохождение автора». Слева появится код класса.
3. Откройте вход ученика в другом окне — удобнее в окне инкогнито — и войдите по коду с любым ником.
4. В панели учителя откройте первый чекпоинт. Ученик увидит его сразу, без перезагрузки.
5. Проходите шаги. Кнопка «Заметка автора» внизу слева сохраняет замечание к текущему шагу. Кнопка «Скопировать результат» в конце чекпоинта даёт текст для чата «Прохождение».
6. Вкладка учителя «Заметки автора» → «Скопировать все» — отправьте их в чат «Сборка», Claude превратит их в правки.

## Как устроен урок

Урок — файл `lessons/urok-NN.js`: цель, донор, линза, `plan` (в каких шагах лежит замысел), `feedback` (колоды понятий и вопросов для отзыва учителя), `wow` (вау-старт: колоды карт, колода секретов, запасная игра) и чекпоинты. Каждый чекпоинт — список шагов типовых видов. Отрисовка всех типов — в `public/student.js` (объект `STEPS`).

| Тип | Что делает | Поля шага |
| --- | --- | --- |
| `play` | Ремейк учителя в рамке, считает партии и рекорд. С `shared: true` — общая игра класса из вау-старта: появляется, когда учитель её раздаст, и считает срабатывания секрета; `secretOff: true` выключает секрет | `game`, `cfg` (значения ручек), `minRounds`, `shared`, `secretOff` |
| `cards` | Колода безумных идей: карты, которые учитель тянет при классе, появляются у всех сразу; голос «перетянуть» | — (колоды — в `wow` урока) |
| `secret` | «Найди секрет»: настоящий секрет игры класса, два чужих из колоды и ловушка — поворот с карты. После догадки — раскрытие и сравнение партий с секретом и без | — |
| `choice` | Карточки (одна или несколько) и ответ своими словами с кубиком | `options`, `multi`, `max`, `own`, `deck` |
| `text` | Короткий текст учителя, кнопка «Понятно» | `html` |
| `sort` | Квиз-мини-игра: разложить карточки по 2–3 лоткам на время, серии, звук, клавиши и геймпад. `wowItems` — карточки из игры класса с подстановками `{hero}`, `{action}`, `{place}`, `{twist}`, `{secret}` | `bins`, `items` (`text`, `bin`, `why`), `wowItems`, `seconds` |
| `factory` | Фабрика: уровень (Базовый, Продвинутый, Босс), карта донора, поля с кубиками и пометкой [кубик] | `levels`, `donorCard`, `fields` (`id`, `label`, `deck`, `levels`) |
| `decisions` | Три решения: чувство, честность, выбор | `fields` |
| `igra` | Промпт ИГРА, черновик собирается из Фабрики по шаблонам `{title}`, `{hero}`… | `fields` (`letter`, `prefill`, `deck`) |
| `producer` | Продюсер читает замысел: находки и развилки кнопками | — |
| `build` | Программист пишет игру, игра запускается в песочнице, ошибки чинятся сами (2 попытки) | `minRounds` |
| `aicheck` | «Найди, где ИИ своевольничал»: догадка ученика, потом записи программиста из `notes` | — |
| `workshop` | Правки по одной: просьба с кубиком, новая версия, откат одним кликом | `deck` |
| `arcade` | Игра одноклассника по кругу или на выбор из аркады, в рамке-песочнице. Рекорд автора, свой и класса; «Рекорд автора побит»; вызов «побей мой мир» после партии | `minRounds` |
| `playtest` | Тап-карточка отзыва на игру из шага `about`: эмоции кнопками, «Нравится / Хочется / А что если» с кубиком. Ниже — открытие плейтеста своей игры и отзыв учителя, обновляются сами | `about`, `emotions`, `decks` (`like`, `want`, `whatif`) |

Новая идея интерактива становится новым типом шага, а не разовой страницей.

## Путь игры ученика

1. Фабрика, решения и ИГРА собираются в замысел (`buildPlan` в `server.js`).
2. Продюсер получает замысел и `ai/producer-prompt.md`, возвращает находки и развилки. Выбор ученика добавляется в задание программисту.
3. Программист получает системный промпт `ai/game-prompt.md` с образцом и шаблон «Новая игра». Сервер достаёт код, проверяет синтаксис и при ошибке сразу просит починить (до 2 раз).
4. Игра открывается по адресу `/play/<игра>/<версия>`, в рамке `sandbox` с заголовком `CSP: sandbox`: код ИИ не видит данных портала даже в отдельной вкладке. Рекорды идут через `postMessage`.
5. Если игра упала, страница ученика сама отправляет ошибку программисту по шаблону «Исправление ошибки». Каждая починка и правка — новая версия; все версии хранятся.
6. Каждый вызов модели записывается в `data/genlog.jsonl`. В записи — модель, время, токены, рубли и итог. Это и есть проверка главного допущения на живых уроках.

## Вау-старт и секрет игры класса

- **Карты при классе.** Вкладка учителя «Вау-старт»: учитель тянет четыре карты из колод `wow.cards` урока (герой, действие, место, поворот). Карты сразу появляются у учеников в шаге `cards`, ученики голосуют «перетянуть». Перетянутая карта сбрасывает голоса.
- **Секрет.** Кубик выбирает секрет из `wow.secrets` случайно, учитель видит его в блоке «Секрет игры» (по умолчанию скрыт — вкладку можно держать на проекторе) и может тайно заменить до сборки. Ученику урок отдаётся без колоды секретов.
- **Сборка.** «Собрать с ИИ» отправляет программисту шаблон «Общая игра урока» из `ai/game-prompt.md`: карты + секрет. Секрет живёт в ручке `secret` с пресетом «Без секрета» и в скрытом счётчике `lab.count('_secret')`. Сервер предупреждает учителя, если ручки или счётчика нет. Каждая сборка — новая версия общей игры класса.
- **Раздача.** Учитель проверяет игру во вкладке и нажимает «Раздать классу» — у учеников игра появляется в шагах `play` с `shared: true`. Пересборка забирает игру у класса до новой раздачи.
- **Запасная игра.** Без ключа ИИ или по кнопке «Запасная игра» общей игрой становится ремейк урока (`wow.fallback`) с названием по картам. Его секрет — свой (`fallback.secret`, ручка `fallback.knob`).
- **Чекпоинт 2.** Шаг `play` с `secretOff` выключает ручку секрета, шаг `secret` спрашивает догадку и только после неё раскрывает секрет (`/api/wow/guess`). Сводка во вкладке учителя: средний лучший счёт с секретом и без, сколько раз сработал секрет, кто угадал и кто попался в ловушку карт.
- **Живые обновления.** Карты, голоса, сборка и раздача рассылают событие `wow`.

## Играем вместе (срез 2)

- **Аркада класса** — `/arcade` для учеников и вкладка «Аркада» у учителя. Каждая собранная игра попадает туда сама, с первой версии. На карточке:
  - название и автор-ник, подпись «по мотивам механики …»;
  - «Что решил я» — три решения ученика;
  - текущая версия и рекорд класса.

  Автор скрывает игру из аркады в «Моих играх»: у одноклассников она пропадает, у автора и учителя остаётся.
- **Личная аркада** — «Мои игры» на `/arcade`: игры по урокам, версии, партии чужих игроков и открытие плейтеста.
- **Рекорды.** Таблица рекордов игры — `scores/<класс>:game:<id>`. Рекорд автора — его лучший счёт в своей игре.
- **Вызов «побей мой мир».** После партии портал выдаёт код из 6 знаков и ссылку `/arcade?ch=КОД`. В вызове записаны игра, версия, зерно и счёт.
  - Принявший вызов играет в `/play/<игра>/<версия>?seed=<зерно>`: оболочка читает зерно из адреса и строит тот же мир.
  - У вызова своя таблица.
  - Если вход не выполнен, ссылка ведёт на вход и после него обратно в аркаду.
- **Телеметрия для автора.** Партия чужого игрока в игре ученика пишется в `games/<id>/plays.jsonl`: счёт, версия, зерно и `tele` из сообщения `over` (`hold`, `presses`, `custom`). Туда же идут нажатия «ещё раз» (сообщение `again`) и карточки плейтеста.
- **Открытие плейтеста** считается только по чужим партиям:
  - сколько партий сыграли и сколько было игроков;
  - сколько раз нажали «ещё раз»;
  - какую кнопку держали дольше всего и какую долю времени. От 50% — «похоже на доминирующую стратегию»;
  - эмоции и карточки соседей.
- **Отзыв учителя** — в карточке ученика в панели: одно понятие геймдизайна и один вопрос, с кубиками из `feedback` урока. Ученик видит отзыв сразу, в шаге `playtest`.
- **Живые обновления.** Новая версия игры, чужая партия и карточка плейтеста рассылают событие `arcade`, отзыв учителя — `feedback`. Шаги `arcade` и `playtest` и страница аркады обновляются без перезагрузки.

## Проверки

```bash
node portal/tools/check-game.js --self   # игры и оболочка в браузере
node portal/tools/e2e-portal.js          # портал целиком: учитель и ученик проходят урок 1
```

`e2e-portal.js` делает два прогона. Первый — с подставным ИИ (`tools/mock-ai.js`):

- продюсер отвечает развилкой;
- первая сборка нарочно падает, и проверка ждёт автопочинку;
- правка даёт новую версию;
- «Играем вместе»: второй ученик собирает игру, ученики играют в игры друг друга, бьют рекорд автора с зажатой клавишей, бросают и принимают вызов на зерне, оставляют плейтест;
- открытие плейтеста видит «→» доминирующей кнопкой, учитель пишет отзыв, и ученик видит его без перезагрузки;
- аркада класса, личная аркада и скрытие игры.

Второй прогон — в демо-режиме: без соседей шаг `arcade` ждёт игру и не падает. Данные пишутся во временную папку, снимки — в `portal/.check/portal-*.png`. Нужен Playwright: `npm i -g playwright && npx playwright install chromium`.

Подставной ИИ можно запустить и вручную, чтобы пройти урок «как с ИИ», но бесплатно. Запуск: `node portal/tools/mock-ai.js 8090`, в `config.json` укажите `"baseUrl": "http://127.0.0.1:8090/v1", "apiKey": "mock"`.

## Безопасность

- Ключ API и пароль учителя хранятся только в `config.json` на сервере. Данные учеников — только в `data/`. Ни то ни другое не попадает в git.
- Ученики входят по коду класса и нику, без фамилий и других личных данных.
- Игры работают в изолированной рамке без доступа к порталу. На хостинге их нужно отдать с отдельного домена (этап 5).
