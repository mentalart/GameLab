# Портал «Лаборатория игр»

Онлайн-портал курса. Готовы ядро игр (этап 1) и каркас портала (этап 3, срезы 1–3).

- Срез 1: вход, урок по чекпоинтам, Фабрика с кубиками, продюсер, сборка игры ИИ с автопочинкой, мастерская правок, панель учителя, заметки автора и журнал генераций.
- Срез 2 «Играем вместе»: аркада класса и личная аркада, игра соседа с рекордом автора, вызов «побей мой мир» на зерне, плейтест тап-карточкой с открытием плейтеста по телеметрии, отзыв учителя.
- Срез 3 «Панель учителя и интерактивы»: проектор с кодом класса, таймером чекпоинта и тем, кто закончил шаг; живой урок с фильтром «застряли»; вау-старт на проекторе (карты урока 1 без секрета и простой вау-старт — шаг `teacher-demo`); квиз-раунды (шаг `rounds`); отчёт журнала генераций по моделям с CSV и сравнением моделей на одном замысле; расход лимитов и «+10 запросов»; статусы заметок автора и выгрузка в Markdown.

- Уроки в портале: 1, 2 и 4 (урок 4 «Глагол и основной цикл» с релизом модуля 1). Урок 3 ещё не собран.

Следующие шаги — в [docs/03_Промпты_следующих_шагов.md](../docs/03_Промпты_следующих_шагов.md).

## Запуск

Нужен Node.js 18 или новее, зависимостей нет.

```bash
node portal/server.js            # или: node portal/server.js 8090 — другой порт
```

При первом запуске сервер создаёт `portal/config.json` и печатает пароль учителя. Адреса:

- `http://localhost:8080/` — вход ученика (код класса + ник) и учителя (пароль);
- `http://localhost:8080/teacher` — панель учителя;
- `http://localhost:8080/projector` — проектор учителя (кнопка «📽 Проектор» в панели открывает его для выбранного класса);
- `http://localhost:8080/arcade` — аркада класса для учеников (вход тем же кодом класса);
- ученики в той же сети открывают адрес, который сервер печатает в строке «Ученики в той же сети».

Без ключа портал работает в **демо-режиме**: продюсер проверяет только простые вещи, а вместо игры ученика собирается образец урока с его названием и решениями. Так можно пройти весь урок и проверить портал бесплатно.

### Подключить ИИ

Откройте `portal/config.json` и заполните:

```json
"ai": {
  "baseUrl": "https://api.provod.ai/v1",
  "apiKey": "ваш ключ provod.ai",
  "codeModel": "anthropic/claude-sonnet-5",
  "textModel": "anthropic/claude-sonnet-5"
}
```

Перезапустите портал. В панели учителя на вкладке «ИИ и расходы» кнопка «Проверить ключ и список моделей» покажет точные id моделей провайдера. Там же модель программиста и продюсера переключается без перезапуска. По умолчанию и игры, и продюсер работают на Claude Sonnet 5 (`anthropic/claude-sonnet-5`); если `textModel` пуста, продюсер берёт модель программиста. Можно переключить на Qwen. Связку карт вау-старта пишет модель программиста: связка — замысел для программиста, а быстрая текстовая модель давала несобираемые игры. Отдельную модель для связки можно задать ключом `"linkModel"` в `ai`. Sonnet 5 не принимает параметр `temperature`: портал не шлёт его моделям Claude, а для других моделей с таким ответом провайдера повторяет запрос без него.

Чтобы журнал считал рубли, впишите цены моделей в `models` (рубли за миллион токенов): `rubPer1MIn` — входящие, `rubPer1MOut` — исходящие, `rubPer1MCacheRead` и `rubPer1MCacheWrite` — чтение и запись кэша (без них кэш считается по цене входа). Цены в `config.example.json` — с provod.ai/ru/pricing на 17.10.2026; запись в кэш у Claude принята за 1,25 цены входа.

**Кэш промпта.** Системный промпт программиста (25–28 тысяч токенов) одинаков для всего класса на уроке. Повторное чтение из кэша у Claude Sonnet 5 стоит 16,75 ₽ за миллион вместо 167,52 ₽, поэтому сборка дешевле примерно на четверть. Qwen, OpenAI, Gemini и DeepSeek кэшируют одинаковое начало запроса сами, Claude — только по метке `cache_control`, её ставит портал. Настройка `ai.cache`: `"auto"` (по умолчанию) — метка для моделей `claude-*`, `"on"` — для всех, `"off"` — без метки; поле `"cache": true/false` у модели в `models` важнее общей настройки. `ai.cacheTtl` — срок кэша, пусто — 5 минут, `"1h"` — час (запись дороже вдвое). Доля входа из кэша видна в панели учителя («ИИ и расходы» → «Все вызовы модели»), токены кэша — в CSV вызовов.

Ограничения в `limits`:

- `aiCallsPerStudentPerLesson` — запросов к ИИ на ученика за урок;
- `rublesPerLesson` — потолок расходов класса на урок, 0 — без потолка.

Оба лимита можно поменять и в панели учителя («ИИ и расходы» → «Лимиты»), без перезапуска: значения из панели лежат в `data/settings.json` поверх `config.json`. Отдельному ученику учитель добавляет запросы кнопкой «+10» в таблице урока.

## Как пройти урок самому (учитель + ученик)

1. Запустите портал и войдите учителем. Пароль — в `portal/config.json`.
2. Создайте класс, например «Прохождение автора». Слева появится код класса.
3. Откройте вход ученика в другом окне — удобнее в окне инкогнито — и войдите по коду с любым ником.
4. В панели учителя откройте первый чекпоинт. Ученик увидит его сразу, без перезагрузки.
5. Проходите шаги. Кнопка «Заметка автора» внизу слева сохраняет замечание к текущему шагу. Кнопка «Скопировать результат» в конце чекпоинта даёт текст для чата «Прохождение».
6. Вкладка учителя «Заметки автора» → «Скопировать все» — отправьте их в чат «Сборка», Claude превратит их в правки.

## Как устроен урок

Урок — файл `lessons/urok-NN.js`: цель, донор, линза, `plan` (в каких шагах лежит замысел), `feedback` (колоды понятий и вопросов для отзыва учителя), `wow` (вау-старт: колоды карт, колода секретов, запасная игра) и чекпоинты. Ещё три необязательных поля:

- `sample: { file, about }` — ремейк урока как второй образец в системном промпте программиста (вместо «Камней мудреца») и как демо-игра без ключа ИИ. Так ИИ видит механику урока, а промпт не растёт с каждым ремейком;
- `demoForks` — развилки демо-продюсера под донора урока, чтобы без ключа продюсер не приносил волну пришельцев в чужую механику;
- `producer: { focus }` — что продюсеру проверить особо на этом уроке (дописывается к его системному промпту).

Каждый чекпоинт — список шагов типовых видов. Отрисовка всех типов — в `public/student.js` (объект `STEPS`).

| Тип | Что делает | Поля шага |
| --- | --- | --- |
| `play` | Ремейк учителя в рамке, считает партии и рекорд. С `shared: true` — общая игра класса из вау-старта: появляется, когда учитель её раздаст, и считает срабатывания секрета; `secretOff: true` выключает секрет. `variants` — варианты той же игры кнопками над рамкой (свои значения ручек, например «классика» и «одно правило»). Счётчики телеметрии (`lab.count`) и скрытый `_secret` копятся по всем партиям шага — их сравнивает шаг `secret` | `game`, `cfg` (значения ручек), `minRounds`, `shared`, `secretOff`, `variants` (`label`, `hint`, `cfg`) |
| `teacher-demo` | Простой вау-старт без секрета (для уроков, где колоды `wow` нет): пока учитель на проекторе тянет карты и собирает игру — «смотри на проектор» и карты вживую, потом игра учителя в рамке. Открывает учитель или таймер шага | `minutes` (через сколько игра откроется сама), `minRounds`, `donorCard`, `decks` (`hero`, `place`, `twist`, `names`), `plan` (шаблоны замысла с `{hero}`, `{place}`, `{twist}`, `{title}`) |
| `cards` | Колода безумных идей: карты, которые учитель тянет при классе, появляются у всех сразу; голос «перетянуть» | — (колоды — в `wow` урока) |
| `abtest` | Слепой тест на игре класса из вау-старта: две одинаковые на вид копии «А» и «Б», в одной ручка секрета выключена. В какой копии секрет — по хешу ника и игры, у соседей по-разному. По `minRounds` партий в каждую, потом голос «где напряжённее» (А, Б, разницы нет). Копит по копиям счёт, время, урон, срабатывания `_secret` и их моменты (`marks`); раскрытие показывает шаг `secret` | `minRounds`, `question` |
| `secret` | «Найди секрет». Без `hunt` — секрет игры класса из вау-старта: настоящий, два чужих из колоды и ловушка — поворот с карты. С `hunt` — секрет донора без игры класса (урок 2): варианты и ловушка из сценария. Ответ, ловушка и раскрытие уходят ученику только после догадки. Потом — итог слепого теста `abtest` (где был секрет, почувствовал ли ученик, цифры копий, полоска с моментами секрета) или сравнение двух шагов `play` | `hunt` (`question`, `options`, `right`, `trap`, `trapText`, `title`, `reveal`, `effect`, `after`, `compare`: `on`, `off`, `onLabel`, `offLabel`, `show` — имена счётчиков) |
| `choice` | Карточки (одна или несколько) и ответ своими словами с кубиком | `options`, `multi`, `max`, `own`, `deck` |
| `text` | Короткий текст учителя, кнопка «Понятно» | `html` |
| `sort` | Квиз-мини-игра: разложить карточки по лоткам на время, серии, звук, клавиши и геймпад. До 3 лотков — клавиши 1 2 3 или ← ↓ →; от 4 до 8 (урок 2: восемь деталей игры) — цифры, стрелки и пробел, крестовина и A; у лотка `example` под названием, после ошибки — `hint` правильного лотка. `wowItems` — карточки из игры класса с подстановками `{hero}`, `{action}`, `{place}`, `{twist}`, `{secret}` | `bins` (`id`, `label`, `example`, `hint`), `items` (`text`, `bin`, `why`), `wowItems`, `seconds` |
| `cycle` | Квиз «Собери цикл» (урок 4): у каждой игры четыре карточки — три шага её основного цикла и одна из другой игры. Ученик собирает цикл по порядку «действие → результат → награда или новая задача», и цикл замыкается стрелкой «↻». Ошибка — подсказка (чужая карточка или не тот шаг), время вышло — цикл показывается сам. Таймер на раунд, серия, очки, разбор после раунда. Клавиши 1–4, стрелки и пробел, геймпад (крестовина, A), тап. Итог с «Скопировать результат» | `rounds` (`game`, `icon`, `cards` — три шага по порядку, `decoy`, `decoyFrom`, `why`), `seconds`, `slots` (подписи шагов, по умолчанию три) |
| `trace` | Квиз «Угадай охотника по следу» (урок 3): в маленьком лабиринте на холсте бегает герой, охотник идёт по одному правилу и оставляет след; ученик называет правило цифрами, стрелками и пробелом, крестовиной и A или тапом. Таймер, серия, звук; после ответа пунктир показывает, куда целился охотник. Правила встроены: `chase` — гонится, `ambush` — наперерез, `flank` — по напарнику (виден красный напарник), `shy` — пугается вблизи, `scatter` — уходит в свой угол, `random` — бродит наугад. Каждое правило из `rules` встретится хотя бы раз | `rules` (`id`, `label`, `why`), `rounds`, `seconds`, `maze` (строки лабиринта, `#` — стена) |
| `predict` | Предсказание динамики (урок 3): ученик выбирает, что будут делать игроки, и записывает предсказание. Потом играет в шаге `play`, и шаг сам, без перезагрузки, сравнивает предсказание со счётчиками телеметрии этого шага в среднем за партию: полоски, главная динамика, «сбылось» или что было чаще всего и почему | `play` (id шага `play`), `question`, `options` (`text`, `counter` — имя счётчика `lab.count`, `why`), `max`, `miss` (начало фразы, если не сбылось) |
| `rounds` | Квиз-раунды на два ответа ◀ ▶ («Игра или не игра?»): клавиши ← → и A D, геймпад (крестовина, стик, плечевые), тап и свайп карточки; таймер, серия, звук, разбор после каждой карточки (дальше — пробел, Enter, A), итог с «Скопировать результат» | `left`, `right` (`label`), `items` (`text`, `side`: `left` или `right`, `why`), `seconds` |
| `factory` | Фабрика: уровень (Базовый, Продвинутый, Босс), карта донора (`donorCard.icon` — свой значок), поля с кубиками и пометкой [кубик]. `donors` — донор на выбор (урок 2: змейка, пинг-понг…): у каждого карта, правила, кнопки и свои колоды кубиков (`decks` по id поля), чтобы кубик не приносил правило из другой игры. В аркаде у игры — выбранный донор | `levels`, `donorCard`, `donors` (`id`, `icon`, `title`, `text`, `rules`, `keys`, `decks`), `fields` (`id`, `label`, `deck`, `levels`) |

| `build` | Программист пишет игру, игра запускается в песочнице, ошибки чинятся сами (2 попытки) | `minRounds` |
| `aicheck` | «Найди, где ИИ своевольничал»: догадка ученика, потом записи программиста из `notes` | — |

| `release` | Релиз модуля (урок 4): выбор лучшей своей игры модуля, не обязательно сегодняшней, партия в рамке и чек-лист версии 1.0. У пунктов с `auto` портал подсказывает, что видно из аркады: подпись донора (`donor`), три решения (`decisions`), чужие партии и «ещё раз» (`plays`), среднее время чужой партии (`time`), число версий (`versions`). | `blind` | Слепой турнир по одной ручке (урок 5) и квиз «Сухая или сочная?» (урок 6): в каждой загадке у ремейка повёрнута одна ручка или включён один переключатель сочности. Вкладки «❓ Загадка» и основа (`baseLabel`, по умолчанию «Как задумано»), ответ открывается после `seconds` секунд игры в загадку; варианты — верный и ещё `choices − 1` из `options`, одни и те же у ученика в раунде. Ошибка — разбор, какая ручка была; итог «угадано N из M» | `game`, `cfg` (общая основа), `rounds` (`cfg`, `answer`, `why`), `options`, `choices`, `seconds`, `question`, `baseLabel`, `after` |
| `blindpair` | Слепая проба игры соседа (урок 6): две одинаковые на вид копии «А» и «Б», в одной выключены все 12 переключателей сочности оболочки. Какая сухая, решает хеш ника и игры. По партии в каждую — голос «куда хочется вернуться» и раскрытие | `about` (id шага `arcade`: игра соседа оттуда, иначе — сосед по кругу), `minRounds`, `question`, `after` |
| `listen` | Квиз «Угадай по звуку» (урок 7): звук раунда собирается на странице из рецепта тонов и шума (как `lab.tone` и `lab.noise`), ученик слушает (▶ или пробел) и выбирает, что случилось в игре: верный ответ и ещё `choices − 1` из `options`, клавиши 1–4. Разбор после каждого ответа, серия, итог «N из M» и что перепутал | `rounds` (`answer`, `sound` — список `{ f, d, w, v, s, at }` для тона или `{ noise: true, d, v, freq, at }` для шума, `why`), `options`, `choices` |
| `sequencer` | Секвенсор мелодии (урок 7): сетка 5 нот × 32 доли (8 тактов), в доле одна нота. Пресеты кубиком, «Послушать» с бегущей долей, «Очистить». «Пробежать» открывает ремейк `game` и отдаёт ему мелодию в `lab.data.melody` — уровень строится по нотам. Готов, когда нот не меньше `minNotes`. Мелодия текстом уходит в черновик ИГРА шаблоном `{melody}` (в `plan` сценария — `melody: id шага`) | `game`, `bpm`, `notes`, `presets` (`label`, `melody` — 32 числа: номер ноты или −1), `bars` (8), `minNotes` (8) |
| `vote` | Выставка джема (урок 8): игры одноклассников этого урока карточками, у каждой «▶ Играть» (партии идут в рекорды класса). Голосование открывается после `minGames` сыгранных игр: в каждой номинации — выбор из игр, в которые ученик сыграл, за свою нельзя. После голоса — итоги класса (лидеры номинаций, `/api/votes`, видны только проголосовавшим) и игра кнопочного турнира — победитель номинации `tournament`. Голоса можно изменить | `nominations` (`id`, `label`, `hint`), `tournament` (id номинации), `minGames` (2) |
| `arcade` | Игра одноклассника по кругу или на выбор из аркады, в рамке-песочнице. Рекорд автора, свой и класса; «Рекорд автора побит»; вызов «побей мой мир» после партии | `minRounds` |
| `playtest` | Тап-карточка отзыва на игру из шага `about`: эмоции кнопками, «Нравится / Хочется / А что если» с кубиком. Ниже — открытие плейтеста своей игры и отзыв учителя, обновляются сами. `predict` — рядом с открытием плейтеста поля Фабрики с предсказанием автора (урок 3: удовольствие и динамика) | `about`, `emotions`, `decks` (`like`, `want`, `whatif`), `predict` (`step`, `field`, `label`) |

Новая идея интерактива становится новым типом шага, а не разовой страницей.

## Путь игры ученика

1. Фабрика, решения и ИГРА собираются в замысел (`buildPlan` в `server.js`).
2. Продюсер получает замысел и `ai/producer-prompt.md`, возвращает находки и развилки. Выбор ученика добавляется в задание программисту.
3. Программист получает системный промпт `ai/game-prompt.md` с образцом и шаблон «Новая игра». Сервер достаёт код, проверяет синтаксис и при ошибке сразу просит починить (до 2 раз).
4. Игра открывается по адресу `/play/<игра>/<версия>`, в рамке `sandbox` с заголовком `CSP: sandbox`: код ИИ не видит данных портала даже в отдельной вкладке. Рекорды идут через `postMessage`.
5. Если игра упала, страница ученика сама отправляет ошибку программисту по шаблону «Исправление ошибки». Каждая починка и правка — новая версия; все версии хранятся.
6. Каждый вызов модели записывается в `data/genlog.jsonl`. В записи — модель, время, токены, рубли, итог, игра и `build` — id сборки, к которой относится вызов. У версии игры — модель, попытки, время и рубли (`ms`, `rub`), `build` и отметка `ran`, когда она запустилась в рамке. Из этого складывается отчёт «с первой попытки» по моделям.

## Вау-старт и секрет игры класса

- **Карты при классе.** Вкладка учителя «Вау-старт»: учитель тянет четыре карты из колод `wow.cards` урока (герой, действие, место, поворот). Карты сразу появляются у учеников в шаге `cards`, ученики голосуют «перетянуть». Перетянутая карта сбрасывает голоса.
- **Колода без повторов.** Карта не выпадает снова, пока класс не вытянет всю колоду, потом колода тасуется заново. Что уже выпало, хранится в классе (`wowSeen`), у `teacher-demo` — в состоянии вау-старта. В уроке 1 в колодах 32–40 карт, места частью адыгейские.
- **Секрет.** Кубик выбирает секрет из `wow.secrets` случайно, учитель видит его в блоке «Секрет игры» (по умолчанию скрыт — вкладку можно держать на проекторе) и может тайно заменить до сборки. Ученику урок отдаётся без колоды секретов.
- **Сборка.** «Собрать с ИИ» отправляет программисту шаблон «Общая игра урока» из `ai/game-prompt.md`: карты + секрет. Секрет живёт в ручке `secret` с пресетом «Без секрета» и в скрытом счётчике `lab.count('_secret')`. Сервер предупреждает учителя, если ручки или счётчика нет. Каждая сборка — новая версия общей игры класса.
- **Раздача.** Учитель проверяет игру во вкладке и нажимает «Раздать классу» — у учеников игра появляется в шагах `play` с `shared: true`. Пересборка забирает игру у класса до новой раздачи.
- **Запасная игра.** Без ключа ИИ или по кнопке «Запасная игра» общей игрой становится ремейк урока (`wow.fallback`) с названием по картам. Его секрет — свой (`fallback.secret`, ручка `fallback.knob`).
- **Чекпоинт 2.** Шаг `play` с `secretOff` выключает ручку секрета, шаг `secret` спрашивает догадку и только после неё раскрывает секрет (`/api/wow/guess`). Сводка во вкладке учителя: средний лучший счёт с секретом и без, сколько раз сработал секрет, кто угадал и кто попался в ловушку карт.
- **Живые обновления.** Карты, голоса, сборка и раздача рассылают событие `wow`.

## Играем вместе (срез 2)

- **Аркада класса** — `/arcade` для учеников и вкладка «Аркада» у учителя. Каждая собранная игра попадает туда сама, с первой версии. На карточке:
  - название и автор-ник, подпись «по мотивам механики …»;
  - «Что решил я» — три решения ученика;
  - текущая версия и рекорд класса.

  Автор скрывает игру из аркады в «Моих играх»: у одноклассников она пропадает, у автора и учителя остаётся.
- **Личная аркада** — «Мои игры» на `/arcade`: игры по урокам, версии, партии чужих игроков и открытие плейтеста.
- **Рекорды.** Таблица рекордов игры — `scores/<класс>:game:<id>`. Рекорд автора — его лучший счёт в своей игре.
- **Вызов «побей мой мир».** После партии портал выдаёт код из 6 знаков и ссылку `/arcade?ch=КОД`. В вызове записаны игра, версия, зерно и счёт.
  - Принявший вызов играет в `/play/<игра>/<версия>?seed=<зерно>`: оболочка читает зерно из адреса и строит тот же мир.
  - У вызова своя таблица.
  - Если вход не выполнен, ссылка ведёт на вход и после него обратно в аркаду.
- **Телеметрия для автора.** Партия чужого игрока в игре ученика пишется в `games/<id>/plays.jsonl`: счёт, версия, зерно и `tele` из сообщения `over` (`hold`, `presses`, `custom`). Туда же идут нажатия «ещё раз» (сообщение `again`) и карточки плейтеста.
- **Открытие плейтеста** считается только по чужим партиям:
  - сколько партий сыграли и сколько было игроков;
  - сколько раз нажали «ещё раз»;
  - какую кнопку держали дольше всего и какую долю времени. От 50% — «похоже на доминирующую стратегию»;
  - эмоции и карточки соседей.
- **Отзыв учителя** — в карточке ученика в панели: одно понятие геймдизайна и один вопрос, с кубиками из `feedback` урока. Ученик видит отзыв сразу, в шаге `playtest`.
- **Живые обновления.** Новая версия игры, чужая партия и карточка плейтеста рассылают событие `arcade`, отзыв учителя — `feedback`. Шаги `arcade` и `playtest` и страница аркады обновляются без перезагрузки.

## Панель учителя и интерактивы (срез 3)

- **Проектор** (`/projector?code=КОД`, кнопка «📽 Проектор» в панели) — страница для экрана класса:
  - крупно адрес и код класса, сколько учеников вошло и сколько на связи;
  - открытый чекпоинт и его таймер. Таймер стартует, когда учитель открывает чекпоинт (из нескольких сразу — первый по уроку), длится `minutes` из сценария. Последняя минута — жёлтая, перебор — красный «+01:20». Кнопки «↻ Таймер заново», «+2 минуты», «Открыть: следующий чекпоинт»;
  - по каждому шагу чекпоинта — полоска «сколько учеников закончили шаг». Имён на проекторе нет.
  - вкладка «Выставка и турнир» — только в уроке с шагом `vote` (урок 8): лидеры трёх номинаций и сколько учеников проголосовало, а под ними — кнопочный турнир в игре-победителе номинации `tournament`. Ученики выходят по одному: учитель вписывает имя, партия попадает в таблицу турнира, лучший счёт наверху. Рамка игры и таблица не сбрасываются при обновлении проектора.
- **Живой урок** во вкладке «Урок»: у открытого чекпоинта — таймер и «закончили: N из M». По каждому ученику:
  - на связи ли он (открыта страница урока или аркады);
  - шаг, где он сейчас, и сколько открытых шагов осталось;
  - «своими словами»: сколько полей во всех ответах урока заполнено и сколько оставлено кубику. От трёх полей кубика ячейка подсвечивается;
  - игра: версии, текущая ошибка и сколько версий падали;
  - запросы к ИИ: «12 из 40», полоска расхода и кнопка «+10»;
  - движение: когда ученик последний раз сохранял ответ или звал ИИ.

  Фильтры: все, «застряли» (нет движения 5+ минут, а в открытых чекпоинтах есть недоделанные шаги — строка красная), «кубик 3+», «ошибка игры», «лимит ИИ на исходе». Сверху — расход ИИ на урок класса: рубли, вызовы и потолок.
- **Вау-старт на проекторе.** Вкладка «Вау-старт» проектора работает с обоими видами вау-старта:
  - урок с колодой `wow` (урок 1, раздел «Вау-старт и секрет игры класса» выше): крупно четыре карты, голоса «перетянуть», «🎲 Тянуть карту» (пробел), «⚙ Собрать игру с ИИ» (Enter), проверка игры и «📣 Раздать классу». Секрет на проектор не выводится: его видит и меняет только панель учителя;
  - урок с шагом `teacher-demo` — простой вау-старт без секрета, описан ниже.
- **Шаг `teacher-demo`** (проверяется уроком-проверкой `tools/fixtures/lessons/urok-90.js`):
  1. Учитель тянет три карты колоды безумных идей пробелом или кнопкой: герой, место, поворот. Карта крутится барабаном. Кубик у карты перетягивает её, кубик у названия — название из колоды `names`, название можно и вписать.
  2. С первой карты идёт обратный отсчёт `minutes` (5 минут). Ученики видят «Смотри на проектор», те же карты и отсчёт вживую.
  3. «⚙ Собрать игру с ИИ» (Enter): замысел «Space Invaders × поворот × мир» собирается из шаблонов `plan` шага. Игра запускается на проекторе. Если упала — программист чинит её сам, до 2 попыток.
  4. Игра открывается у всех, когда выйдет время, или раньше — кнопкой «▶ Открыть всем сейчас». «⏸ Скрыть от учеников» держит её закрытой. Ученики играют в рамке, рекорды — общая таблица класса по этой игре.

  Игра учителя хранится отдельно для каждого урока класса (`classes/<код>/demo-<урок>.json`), в аркаду класса не попадает. «↺ Новые карты» начинает вау-старт заново.
- **Отчёт журнала генераций** («ИИ и расходы») — проверка главного допущения. Одна строка — одна собранная игра: сборка ученика, вау-старт или сравнение, вместе с её починками. По каждой модели:
  - доля игр, заработавших с первой попытки: сборка без починки синтаксиса, игра запустилась в рамке (сообщение `ready`) и не упала. Доля считается по играм, которые хоть раз запускались;
  - доля игр, которые работают в итоге, после починок;
  - среднее число починок (синтаксиса на сервере и ошибок в рамке), среднее время и рубли на одну игру;
  - сколько игр ещё не запускали и сколько сборок не дали игры вовсе.

  Кнопки «⬇ CSV по играм» и «⬇ CSV всех вызовов» выгружают таблицы для Excel: разделитель «;», UTF-8 с BOM. Демо-сборки в отчёт не входят.
- **Сравнение моделей на одном замысле.** В карточке ученика — «⚖ Пересобрать другой моделью». Замысел, по которому ученик собирал игру, сохранён в игре (`plan`); его пишет выбранная модель, она же чинит свои ошибки. Пересборка — отдельная игра учителя (`compareOf`), её нет у ученика и в аркаде. Версии A (ученик) и B, C… (учитель) открываются в одной рамке по очереди. В отчёте сравнения стоят рядом.
- **Лимиты.** Расход урока класса и «12 из 40» по ученикам видны в панели. «+10» и «+5» добавляют ученику запросов на этот урок (`aiBonus`), ученик сразу получает уведомление. Общие лимиты правятся во вкладке «ИИ и расходы».
- **Заметки автора со статусом:** новая, в работе, сделано. Фильтр по статусу, «⧉ Скопировать» в Markdown и «⬇ Markdown» — файл, сгруппированный по статусам, с чек-боксами `- [ ]` и `- [x]`. Статусы лежат в `data/notes-status.json`, сами заметки не меняются.

## Проверки

```bash
node portal/tools/check-game.js --self   # игры и оболочка в браузере
node portal/tools/e2e-portal.js          # портал целиком: учитель и ученик проходят уроки 1–8 (--from=5 — с урока 5, для отладки)
node portal/tools/build-prompt.js --sizes  # размер промпта программиста для каждого урока
```

`e2e-portal.js` делает два прогона. Первый — с подставным ИИ (`tools/mock-ai.js`):

- продюсер отвечает развилкой;
- первая сборка нарочно падает, и проверка ждёт автопочинку;
- правка даёт новую версию;
- «Играем вместе»: второй ученик собирает игру, ученики играют в игры друг друга, бьют рекорд автора с зажатой клавишей, бросают и принимают вызов на зерне, оставляют плейтест;
- открытие плейтеста видит «→» доминирующей кнопкой, учитель пишет отзыв, и ученик видит его без перезагрузки;
- аркада класса, личная аркада и скрытие игры;
- срез 3: проектор (код, таймер, кто закончил шаги, карты вау-старта урока 1 без секрета), сравнение моделей (`mock-alt` собирает без ошибок), фильтр «застряли», «+10 запросов», расход урока, статус заметки и Markdown, отчёт по моделям и оба CSV.

В конце каждого прогона учитель переключает класс на урок-проверку `tools/fixtures/lessons/urok-90.js`: вау-старт `teacher-demo` на проекторе (карты пробелом, ученик видит их вживую, сборка при всех, автопочинка упавшей игры, «открыть всем», ученик играет).

Потом — урок 2 в обоих прогонах: донор «Камни мудреца» с ручками из шага, вариант «Ветер с Фишта», «Найди секрет» донора (ответ не уходит ученику заранее, ловушка или угадано, сравнение счётчиков классики и правила), квиз-раунды «Игра или не игра?» свайпом, кнопкой и клавишами, сортировщик на 8 лотков с подсказкой после ошибки, Фабрика с донором «Пинг-понг» и его колодой, черновик ИГРА по правилам донора, сборка (с ИИ — с автопочинкой), донор игры в аркаде и дуэль вдвоём за одним экраном.

Потом — урок 3 в обоих прогонах: донор «Ночной лабиринт» с секретом, предсказание динамики («волки пойдут хвостом») и его сравнение с телеметрией партии «одно правило» без перезагрузки, «Найди секрет» (ловушка «волки быстрее» или угадано, сравнение окружений и хвоста), квиз «Угадай охотника по следу» цифрами и стрелками с пробелом, квиз «Механика, динамика или эстетика?», Фабрика MDA с колодами урока (охотники, удовольствие, динамика), черновик ИГРА с характерами охотников, демо-продюсер с развилкой урока, образец урока 3 в промпте программиста (с ИИ) или демо-сборка «Ночного лабиринта» с названием ученика, дуэль с Вожаком (ручка `vs` включает двух игроков: стрелки — у второго) и предсказание автора в плейтесте.

Потом — урок 4 в обоих прогонах: донор «Каменный стакан» с мешком и предпросмотром и он же без секрета (ручки из шага), «Найди секрет» (ответ не уходит заранее, ловушка «камни падали медленнее» или угадано, сравнение засух и линий), квиз «Собери цикл» мышью, стрелками и цифрами с чужой карточкой и подсказкой, Фабрика с колодой падающих фигур, черновик ИГРА с наградой за линию, демо-продюсер с развилками урока, сборка — программист получает образец «Каменный стакан» (подставной ИИ запоминает системный промпт), в демо-режиме игра ученика — «Каменный стакан» с его названием, промпт урока не больше 25 тысяч токенов; релиз модуля: три игры модуля на выбор, подсказки чек-листа из аркады, релиз не выходит без чек-листа, метка 1.0 одна на модуль, учитель видит релиз в аркаде; дуэль двух стаканов: оболочка переключается на двоих ручкой `vs`, игроки роняют камни своими клавишами, вариант «Без секрета»; самооценка модуля.

Потом — урок 5 в обоих прогонах: донор «Тур над Хаджохом» бежит и прыгает с клавиатуры, сырой прыжок (ручка `secret` из шага) «глотает» нажатие чуть позже края, «Найди секрет» (ловушка «прыгал выше» или угадано, сравнение потерянных нажатий), лаборатория прыжка с вариантом «Луна», слепой турнир по одной ручке (загадка с одной повёрнутой ручкой, ответ закрыт, пока не поиграл, «Как задумано», разбор ошибки, итог), Фабрика и сборка с образцом урока, демо-игра урока, спидран без огоньков с призраком лучшей попытки.

Потом — урок 6 в обоих прогонах: «Ледолом» и 12 переключателей сочности оболочки 0.3 (своя группа в ручках, `lab.pitch`, пресет «Без секрета» выключает все, «Как задумано» включает обратно), сухой «Ледолом» из шага глушит эффекты в самой оболочке, «Найди секрет» (ловушка «хычин летал быстрее» или угадано), квиз «Сухая или сочная?» (вкладка «Сухая» — все выключены, в загадке включён один), Фабрика и сборка с образцом урока, кооператив двух лопат по ручке `coop`, слепая проба игры соседа: в одной копии сухо, голос и раскрытие (в демо-режиме без соседей шаг ждёт игру).

Потом — урок 7 в обоих прогонах: «Шаг в такт» на одних часах (щелчок перед каждым кувшином) и без секрета (щелчков нет, кувшины те же), «Найди секрет» с ловушкой «танцор бежал медленнее» или угадано, сравнение «идеально» и «мимо»; предсказание «что будет без звука» и партия с выключенным переключателем «Звук», сравнение с телеметрией; квиз «Угадай по звуку» клавишей и кнопкой; секвенсор: пресет, своя нота, «Послушать», «Пробежать» — ремейк получает мелодию в `lab.data` и ставит кувшин на каждую ноту; черновик ИГРА с мелодией, образец «Шаг в такт», демо-игра урока; ритм-дуэль по ручке `duel`.

Потом — урок 8 в обоих прогонах: «Башня до неба»: промах 6 см с окном «идеально» — плита ровно, без секрета — отрезан; «Найди секрет» с ловушкой «плиты ехали медленнее» или угадано, квиз модуля «Какой это приём?», джем с донором Stack из колоды «одна кнопка» (кубик из колоды Stack, правила классики в черновике ИГРА), образец «Башня до неба», демо-игра урока; релиз модуля 2 — на выбор только игры уроков 5–8, метка 1.0; две башни вдвоём по ручке `duel`; журнал «три приёма ощущения игры». С подставным ИИ — выставка: вторая ученица собирает игру джема, на выставке только игры джема одноклассников, голосование открывается после партии, итоги класса и игра турнира; проектор: лидеры номинаций, партия турнира в таблице, рамка живёт после обновления.

Второй прогон — в демо-режиме: без соседей шаг `arcade` ждёт игру и не падает. Урок-проверку портал видит только с переменной `LAB_LESSONS`, её ставит `e2e-portal.js`. Данные пишутся во временную папку, снимки — в `portal/.check/portal-*.png`. Нужен Playwright: `npm i -g playwright && npx playwright install chromium`.

Подставной ИИ можно запустить и вручную, чтобы пройти урок «как с ИИ», но бесплатно. Запуск: `node portal/tools/mock-ai.js 8090`, в `config.json` укажите `"baseUrl": "http://127.0.0.1:8090/v1", "apiKey": "mock"`.

## Безопасность

- Ключ API и пароль учителя хранятся только в `config.json` на сервере. Данные учеников — только в `data/`. Ни то ни другое не попадает в git.
- Ученики входят по коду класса и нику, без фамилий и других личных данных.
- Игры работают в изолированной рамке без доступа к порталу. На хостинге их нужно отдать с отдельного домена (этап 5).
