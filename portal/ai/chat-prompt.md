# Задание для Qwen в чате

Игры во всех уроках пишет Qwen в бесплатном чате chat.qwen.ai (решение автора 18.10.2026). Портал не зовёт модель: он даёт задание кнопкой «Скопировать», человек вставляет его в чат, а ответ — обратно в портал. Задание на новую игру одно, из четырёх частей, ответ — одна страница HTML без Babylon.js:

1. просьба автора — `собери яркую lowpoly 3d игру для школьников на html`;
2. гейм дизайн документ — у игры класса карты, документ (связка карт) и спрятанная механика, у своей игры ученика его замысел (Фабрика, решения, ИГРА, развилки продюсера);
3. картинка — раздел `look` ниже: что значит «ярко» по пунктам (решение автора 18.10.2026: Qwen3.8-Max без него писал игры без багов, но невзрачные, а Omni-Flash — яркие, но с ошибками; с разделом Max получает картинку по пунктам);
4. что нужно порталу — раздел `portal` ниже: один файл HTML, управление с клавиатуры и джойстика, объект `portal` (ручки, конец партии, рекорд, счётчики).

Раздел `look` идёт во все задания на новую игру (игра класса, своя игра ученика) и в перенос игры в новый чат (`move`). В правку, починку, договор и просьбу из конструктора — одна строка «картинку не упрощай», чтобы Qwen не перерисовывал игру на каждую мелкую просьбу. Больше в задании ничего нет: ни правил геймдизайна, ни образцов. Объект `portal` даёт мост `portal/engine/portal.js`: портал вставляет его в каждую игру-страницу сам. Правки и починки игры-страницы — разделы `change`, `fix` и формат кусками `patch`; прежняя игра-объект GAME правится по `game-prompt.md`.

Портал берёт текст между метками `chat:имя:start` и `chat:имя:end` и подставляет поля в квадратных скобках. Меняйте текст здесь, код (`lib/ai.js`, функции `chatBuild`, `chatShared`, `chatChange`, `chatFix`) трогать не нужно.

## Картинка

<!-- chat:look:start -->
# Картинка
С первого кадра игра выглядит ярко и живо — как инди-игра, а не как проверка движка:
- палитра из 4–6 насыщенных цветов; у героя, врагов, бонусов и земли разные цвета, героя видно сразу;
- небо — градиент или цветной фон, туман в цвет неба: даль мягко растворяется;
- свет: мягкий общий (небо и земля) и тёплое солнце с тенью, тени холоднее света; материалы с flatShading, свечение (emissive) только у бонусов и опасностей;
- у игры есть свой фирменный приём, по которому её узнают с одного кадра (светящийся след, необычное небо, особая форма героя), — назови его в portal.notes;
- мир заполнен: вокруг поля игры не меньше 30 декоративных объектов из примитивов (деревья, камни, дома, облака), земля не пустая плоскость;
- всё живёт: бонусы крутятся и покачиваются; подбор, удар и гибель — вспышка частиц и звук; урон — тряска камеры и красная вспышка экрана; счёт подпрыгивает, когда меняется; на сильном ударе — стоп-кадр на 0,05 секунды, герой сжимается и растягивается при прыжке и ударе; ничто на экране не стоит идеально неподвижно; каждый эффект короткий и тише, чем хочется;
- камера плавно следует за героем (lerp) под углом сверху;
- экраны и счёт — крупный жирный шрифт с тенью или обводкой на полупрозрачной плашке;
- плавно и на слабом школьном компьютере: одна тень от солнца, не больше 200 частиц разом, setPixelRatio не больше 2.

## Что нужно порталу

<!-- chat:portal:start -->
# Что нужно порталу
Игра откроется в портале курса внутри рамки-песочницы.
- Один файл HTML: весь код внутри, библиотеки — только с CDN (например, three.js через importmap с unpkg или jsdelivr). Моделей и звуков из файлов нет: лоуполи-фигуры собери из примитивов, звуки — через Web Audio.
- Ответ — только код одним блоком ```html, от <!DOCTYPE html> до </html>, без пояснений до и после.
- Управление с клавиатуры и с джойстика (геймпада) одновременно. Геймпад опрашивай каждый кадр через navigator.getGamepads(): левый стик и крестовина — движение, кнопка A (0) — главное действие, B (1) — второе, Start (9) — старт и пауза. Клавиатура: стрелки и WASD — движение, пробел — A, Shift — B, Enter — старт, R — заново. Подписи кнопок на экранах пиши парой: `<span class="keys-only">Пробел</span><span class="pad-only">A</span>` — портал сам показывает подписи геймпада, когда он подключён или нажата его кнопка, и подписи клавиатуры, когда нажата клавиша.
- Экраны: старт (название, цель одной фразой, управление; закрывается по Start, A, Enter или пробелу), игра со счётом на экране, конец партии (счёт, рекорд класса; закрывается и сразу начинает новую партию по Start, Enter или R, перезапуск быстрее секунды; кнопка A и пробел его не закрывают — ими только что играли).
- В странице уже есть объект portal, не создавай его:
  - ручки геймдизайнера: `const cfg = portal.knobs({ speed: { value: 8, min: 2, max: 20, step: 0.5, label: 'Скорость героя' }, ... }, { 'Новичок': { speed: 5 } })` — вызови один раз при загрузке. Каждое важное число игры (скорость, частота, сила, жизни, время) — ручка; в коде читай `cfg.speed` каждый раз, когда число нужно, не копируй в свои переменные. Пресет «Новичок» обязателен. Панель ручек открывается по Tab и Select, её рисует портал;
  - `portal.paused` — открыта панель ручек: пока true, игра стоит;
  - `portal.over(очки)` — в конце каждой партии; `portal.again()` — когда начинается новая партия;
  - `portal.onRecord = (record, best) => { ... }` — рекорд класса `record` ({ nick, score } или null) и свой лучший `best`: покажи их на экране конца партии;
  - `portal.count('событие')` — ключевые события партии: выстрел, прыжок, подбор;
  - `portal.score(очки)` — каждый раз, когда меняется счёт; `portal.hurt()` — каждый раз, когда герой получает урон: по ним портал рисует ученику полоску партии;
  - `portal.notes(['...', '...'])` — вызови один раз при загрузке: 3–6 коротких строк, что ты решил сам, чего не было в задании (например, «враги стреляют в ответ», «камера сверху»). Обновляй их при каждой правке.
- Нельзя: localStorage, sessionStorage, cookies, alert, confirm, prompt, fetch, новые окна — в песочнице они не работают, рекорды хранит портал.
<!-- chat:portal:end -->

## Спрятанная механика

Добавляется к связке игры класса и к замыслу ученика с картой спрятанной механики. `[база]` — поле `base` спрятанной механики из колоды урока, `[как]` — поле `howto`: геймплей спрятанной механики по шагам (Qwen по одному эффекту собирал спрятанную механику невнятно, 18.10.2026).

<!-- chat:secret:start -->
Спрятанная механика — её нет на картах, класс будет искать её, когда сыграет: [секрет]
Спрятанная механика прячет правило, а не эффект: эффект крупный и на экране, игрок видит его, но не знает, почему так. Первое срабатывание — до 15-й секунды, у новичка не меньше 4 раз в минуту; эффект меняет скорость, очки или время в 2–3 раза, с картинкой и звуком рядом с героем. В этой игре только спрятанная механика делает вот что: [база] Без спрятанной механики этого в игре нет совсем.
[как]
Для портала: ручка secret в portal.knobs — { value: 1, min: 0, max: 2, step: 0.05, label: 'Спрятанная механика' } (подпись не называет механику); при cfg.secret === 0 механики нет, при 2 — она вдвое сильнее; пресет 'Без спрятанной механики': { secret: 0 }; каждый раз, когда спрятанная механика срабатывает, вызывай portal.count('_secret'), у постоянного эффекта — раз в секунду, пока он заметно сильнее, чем без спрятанной механики. Правило спрятанной механики нигде в игре не названо.
<!-- chat:secret:end -->

## Правка в чате своими словами (урок 1, чекпоинт 5)

Ученик пишет просьбу сам в том чате, где Qwen собирал его игру, и вставляет ответ в портал кнопкой «Вставить новую версию из чата». Чтобы Qwen отвечал в формате, который портал примет, перед первой правкой ученик один раз отправляет договор `pact`. Если чата нет (закрыт, другой компьютер) — сообщение `move`: правила портала, текущий код и договор. Конструктор просьбы собирает сообщение `ask` из находки разбора. Если в новой версии пропали ручки, спрятанная механика или конец партии, портал даёт сообщение `repair`.
