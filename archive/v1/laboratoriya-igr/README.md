# Лаборатория игр — платформа урока 1

Локальный сайт для курса геймдизайна. Учитель запускает его на своём компьютере, ученики открывают в браузере на своих компьютерах в той же сети. Все проходят одну и ту же последовательность урока, а замыслы, игры и Аркада у каждого свои. Код игр пишет Qwen через облачный API.

## Что нужно

- Компьютер учителя с Windows, macOS или Linux.
- **Node.js 18 или новее** (версия LTS с https://nodejs.org). Больше ничего устанавливать не нужно.
- Ключ API Qwen (Alibaba Cloud Model Studio, он же DashScope). Без ключа платформа работает в **демо-режиме**: все шаги урока проходятся, но вместо ответов Qwen подставляются заготовки. Это удобно для репетиции.
- Ученики и учитель в одной сети (один Wi-Fi или школьная сеть).

## Запуск за 5 минут

1. Распакуйте архив в любую папку.
2. Запустите `Запустить (Windows).bat` (на Mac — `Запустить (Mac).command`, на Linux — `node server.js` в папке).
   При первом запуске появится файл `config.json` и случайный пароль учителя.
3. Откройте `config.json` в Блокноте и вставьте ключ Qwen в поле `"apiKey"`. Сохраните и перезапустите сервер.
4. В окне сервера будут написаны:
   - адрес для учеников, например `http://192.168.1.15:8080`;
   - **код класса** из 4 цифр;
   - адрес панели учителя `http://localhost:8080/teacher` и пароль.
5. Windows спросит про брандмауэр — разрешите доступ **для частных сетей**. Иначе ученики не увидят сайт.
6. Напишите на доске адрес и код класса. Ученики входят по имени и коду.

## Как вести урок

Панель учителя управляет темпом. Ученики видят шаги только до открытого чекпоинта, дальше — экран «Ждём учителя».

| Чекпоинт | Что делают ученики | Что делает учитель |
| --- | --- | --- |
| 1. Вау-старт | Играют в общую игру, крутят ручки, отвечают на вопросы плейтеста, получают отзыв | По желанию собирает новую общую игру вместе с классом: тянет карты кубиком или записывает идею, которую выкрикнули ученики, и нажимает «Раздать классу». По умолчанию общая игра — «Сова-хакер» |
| 2. Кто такой геймдизайнер | Читают о ролях в команде, проходят квиз «Чьё это решение?» | Открывает чекпоинт, когда большинство закончило плейтест |
| 3. Твоя первая игра | Заполняют форму «ИГРА» с кубиками, получают отзыв ИИ-продюсера и решают развилки, собирают игру, правят её, проводят плейтест | Смотрит в таблице, кто ждёт Qwen, открывает карточку ученика, видит его задание и пометки «[кубик]» |
| 4. Аркада | Видят свою Аркаду: общую игру и свою, достижения, XP, линзу, пишут открытие дня | Открывает «Аркаду класса» на проекторе для общего плейтеста |

Совет: прорепетируйте урок в демо-режиме (без ключа) — откройте сайт в двух вкладках как ученик и как учитель.

## Как устроена генерация игр

Qwen пишет не всю игру, а только объект `GAME` для готового движка (`engine/template.html`). Движок уже умеет: экран старта с решениями дизайнера, экран конца, паузу, счёт и жизни, панель «Ручки геймдизайнера» (Tab), клавиатуру, **геймпад с переключением подсказок на его кнопки**, тач-кнопки на планшетах, звук, частицы, тряску и запись статистики для плейтеста. Поэтому игры получаются стабильнее, а стандарт студии соблюдается всегда.

Если код с ошибкой, сервер сам просит Qwen исправить его. Если игра падает уже в браузере, ученик видит понятное сообщение и кнопку «Починить игру» — ошибка уходит в Qwen автоматически.

Игры запускаются в изолированном фрейме: они не видят сайт, данные учеников и интернет.

## Файлы, которые можно менять

- `lessons/lesson1.js` — весь сценарий урока: тексты учителя, вопросы плейтеста, квиз, колоды для кубиков.
- `prompts.js` — инструкции для Qwen: программист, продюсер, отзыв учителя, фильтр слов.
- `config.json` — ключ, модели, порт, пароль учителя, лимиты.
- `games/sova-haker.html` — общая игра по умолчанию.

После изменений перезапустите сервер.

## Настройки в config.json

| Поле | Что значит |
| --- | --- |
| `qwen.apiKey` | Ключ API. Можно также задать переменную окружения `DASHSCOPE_API_KEY` |
| `qwen.baseUrl` | Адрес OpenAI-совместимого API. По умолчанию международный: `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` |
| `qwen.codeModel` | Модель для кода игр, по умолчанию `qwen3-coder-plus` |
| `qwen.chatModel` | Модель для продюсера и отзывов, по умолчанию `qwen-plus` |
| `qwen.maxConcurrent` | Сколько запросов к Qwen идёт одновременно, остальные ждут в очереди |
| `limits.generationsPerStudent` | Сколько раз ученик может собрать игру с нуля за занятие |
| `limits.fixesPerGame` | Сколько правок одной игры |
| `demoMode` | `true` — принудительно демо-режим, даже если ключ задан |

Названия моделей и адрес API меняются: проверьте актуальные в консоли Alibaba Cloud Model Studio перед уроком. Подойдёт и любой другой OpenAI-совместимый сервис с моделями Qwen, в том числе свой сервер с vLLM или Ollama — достаточно поменять `baseUrl`, `apiKey` и названия моделей.

## Данные

Всё хранится в `data/db.json` на компьютере учителя: имена (как ввели ученики), ответы, код игр. В облако уходят только тексты замыслов, ответы плейтеста и код игр — в запросах к Qwen, без имён учеников (подпись автора добавляется к игре уже на компьютере учителя). Кнопка «Начать с новым классом» в панели учителя сохраняет резервную копию и очищает учеников.

## Если что-то не работает

- **Ученики не открывают сайт.** Проверьте, что они в той же сети, и что брандмауэр разрешил Node.js. Попробуйте другой адрес из окна сервера.
- **«Нет связи с Qwen».** Проверьте интернет на компьютере учителя, ключ и `baseUrl`. Кнопка «Проверить связь с Qwen» в панели учителя покажет ошибку.
- **Игра собирается дольше двух минут.** Посмотрите в панели «в очереди»: если учеников много, уменьшите очередь, увеличив `maxConcurrent`, или раздайте задание партиями.
- **Ученик закрыл вкладку.** Пусть откроет адрес снова: вход сохраняется в браузере. На другом компьютере — то же имя и кнопка «Это я».
- **Сервер нужно перезапустить посреди урока.** Ничего не потеряется, кроме запросов к Qwen, которые были в работе в этот момент.
