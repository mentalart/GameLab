## Решения версии 2.0 (решения автора, 17.10.2026)

- **Механики-доноры.** Каждое занятие строится вокруг яркой механики известной игры. Своя игра ученика собирается по формуле Донор × Твист × Мир. Спрятанная механика донора — скрытый приём, который делает механику приятной, — и есть понятие занятия.
- **Qwen пишет каждую игру ученика целиком** на общей основе Лаб3D. Ремейк донора учителя — вход занятия на 1–2 минуты и образец механики для Qwen, а не каркас.
- **Движок — Babylon.js** (отменено 18.10.2026, см. ниже «Babylon.js в курсе не используется») одной закреплённой версии с физикой Havok и CC0-моделями Kenney, Quaternius и KayKit. Всё лежит на сервере портала, без CDN. Qwen получает шпаргалку по API этой версии и 3–5 рабочих ремейков как образцы. Запасной вариант — three.js с Rapier; Godot — ступень для желающих после курса.
- **Онлайн-портал.** Разработка идёт в репозитории, портал запускается локально или в облачной среде. Рабочий режим — хостинг в России: у учеников персональные данные несовершеннолетних. Пробный выезд на хостинг после модуля 1.
- **Социальный крючок в каждой игре** с занятия 1: рекорд класса, второй игрок, призрак, зерно-вызов, код уровня, открытка с результатом.
- **Релиз в конце каждого модуля:** лучшая игра модуля доводится до версии 1.0 по чек-листу.
- **Занятие 13** — дуэль на линии по мотивам Clash Royale; оборона по линиям по мотивам Plants vs. Zombies уходит на занятие 24.
- **Модуль 7** — сетевая арена всего класса через сервер портала.
- **Курс собирается заново с урока 1.** Уроки 1–2 переписаны под формулу с донором: урок 1 — Space Invaders, урок 2 — классика + одно правило.
- **Правки сразу в main** (17.10.2026). Ветки и запросы на слияние не нужны. В Claude Code коммит и отправку в main делает хук автокоммита.
- **Один образцовый ремейк для Qwen на старте** (17.10.2026): «НЛО в станице» (до 17.10.2026 — «Тарелки над аулом»). Новые образцы добавляются по мере уроков.
- **Отдельной проверки Qwen нет** (17.10.2026). Модель программиста переключается в панели учителя: если Qwen не справится, игры пишет Claude Sonnet 5 через тот же provod.ai. Каждый вызов модели попадает в журнал генераций: время, токены, рубли, починки. Так проверка идёт на живых уроках.
- **Продюсер тоже на Claude Sonnet 5** (решение автора 17.10.2026). Qwen портал по умолчанию не использует: `textModel` в `config.example.json` — `anthropic/claude-sonnet-5`, а пустая `textModel` берёт модель программиста. Продюсер пишет короткий текст, на Sonnet это около 1 ₽ за замысел.
- **Правка ученика — кнопками и своими словами, на уроке 1 одна** (решение автора 17.10.2026). В Мастерской кнопки «Слишком легко», «Слишком сложно», «Непонятно, что делать», «Скучно в середине», «Героя плохо видно», «Вяло, мало сочности» дают программисту точную инструкцию, к ней можно дописать свои слова. Число правок на уроке — поле `limit` шага `workshop`, его проверяет сервер; урок 1 — одна правка. Причина: свободная просьба школьника ломала игру, а каждая правка Sonnet стоит почти как сборка. С 17.10.2026 на уроке 1 две правки: одна после своих партий, вторая после плейтеста соседа (см. «Урок 1: правки по разбору геймдизайнера»).
- **Занятие — 3 часа с переменой** (решение автора 17.10.2026): 80 минут, перемена 20 минут, 80 минут. Количество занятий не меняется, растёт суммарное время курса.
- **Инструкции проекта в Claude — только указатель на репозиторий** (17.10.2026): стандарты, статус и порядок работы хранятся в журнале и `CLAUDE.md`, копии в Claude нет.
- **Портал собирается срезами** (17.10.2026). Срез 1 — урок проходится от входа до своей игры и правок. Срез 2 — «Играем вместе». Срез 3 — панель учителя и интерактивы. Следующие шаги можно делать в других аккаунтах Claude по готовым промптам из `docs/03_Промпты_следующих_шагов.md`.

- **Программист во всех уроках — Qwen в бесплатном чате chat.qwen.ai** (решение автора 18.10.2026: «игры я создаю только через chat.qwen.ai»). Версия 2 урока 1 стала единственным уроком 1, версия 1 (программист через API) удалена; класс, открытый на `urok-01-v2`, открывает урок 1. API для игр не используется вовсе: сборка своей игры, игра класса, игра при всех, правки, починки и правка по отчёту бота открывают окно «Скопировать задание → Открыть chat.qwen.ai → Вставить ответ». Продюсер, связка и черновик отзыва остаются на API. Как устроено:
  - задание ждёт человека (`progress.ask` в `startJob`, `/api/job/prompt`, `/api/job/answer`, `/api/job/cancel`), окно — `chatDialog` в `public/common.js`, поэтому оно работает у ученика, учителя и на проекторе без правок шагов;
  - **задание на новую игру одно — из четырёх частей** (решение автора 18.10.2026: «Задание для Qwen работает как надо, игры получаются хорошие»): просьба автора «собери яркую lowpoly 3d игру для школьников на html», гейм дизайн документ (у своей игры — замысел ученика), «Картинка» (что значит «ярко» по пунктам) и «Что нужно порталу» (`portal/ai/chat-prompt.md`). Прежнее задание с правилами Лаб3D и образцом убрано вместе с кнопкой. Ответ — одна страница HTML без Babylon.js; связь с порталом даёт мост `portal/engine/portal.js`, портал вставляет его в игру сам: `portal.knobs` (ручки, панель по Tab или Select, пресеты, setCfg для копий А и Б), `portal.over`, `portal.onRecord`, `portal.count('_secret')`, сообщения «запустилась» и ошибки со строкой;
  - код из ответа проверяется; если ответ не подошёл, портал выдаёт следующее сообщение в тот же чат; оборванный ответ — просьба «Продолжи» и склейка частей (до 4 продолжений). Правка и починка идут в формате той игры, что есть: страница HTML — по `chat-prompt.md`, объект GAME для оболочки «Лаб3D» (так отвечает подставной Qwen в проверках) — разделами `*-game` того же файла. В игру-страницу бот-плейтестер не играет;
  - правок без лимита (чат бесплатный), лимит запросов и рублей на них не действует; **сравнения моделей и «Запасной игры» больше нет** (решение автора 18.10.2026); новая сборка игры учителя отменяет задание, которое ждёт ответа;
  - проверки: `node portal/tools/e2e-qwen-chat.js` (окно Qwen, задание, мост) и `node portal/tools/e2e-portal.js` — в нём программиста подменяет подставной Qwen (`LAB_CHAT_AUTO`, `chatAnswer` в `tools/mock-ai.js`: ответ вставляется сам). Разбор рисков (аккаунты учеников, доступность из школы, обрывы) — `qwen-chat/план.md` в файлах проекта.
- **Babylon.js в курсе не используется** (решение автора 18.10.2026). Доноры уроков переделываются без Babylon.js с лучшей графикой, эффектами и ощущением от игры по разбору лучших игр жанра, потом всё, что связано с Babylon.js, удаляется. Этапы — отдельными сессиями, каждый заливается в main по готовности. Удалено 19.10.2026 (этап D, см. «Ядро игр на three.js»).

## Ядро игр (этап 1, 17.10.2026)

Историческая запись: оболочка Babylon, `game-prompt.md`, `claude-prompt.md` и `build-prompt.js` удалены 19.10.2026 и остались в истории git. Правила хорошей игры из `claude-prompt.md` живут в skill `lab3d-igra` (`pravila.md`).

- **Babylon.js 9.31.0 и Havok 1.3.14** лежат в `portal/engine/vendor/`. Обновляются только workflow `vendor-babylon.yml`, потому что среда Claude не видит npm и CDN. Типы `babylon.d.ts` той же версии — по ним сверяется шпаргалка для Qwen.
- **Оболочка «Лаб3D» 0.1** (`portal/engine/lab.js`) — служебный слой, а не движок. Qwen пишет обычный Babylon внутри объекта GAME, а стандарты курса оболочка выполняет сама:
  - экраны старта, паузы и конца партии, перезапуск R;
  - клавиатура, два геймпада и тач;
  - «Ручки геймдизайнера» с пресетами и «Как задумано»;
  - камеры, тени, свечение, частицы, звук без файлов;
  - зерно партии, телеметрия, рекорды;
  - ошибка со строкой кода и связь с порталом.
- **Короткое нажатие не теряется** даже при 5–10 кадрах в секунду: оболочка запоминает нажатие до следующего кадра. Нажатие, которым запущена партия, по-прежнему не засчитывается.
- **Копии вместо клонов.** Повторяющиеся предметы делаются через `createInstance` от скрытого исходника. Копии рисуются пачкой и отбрасывают тени. Бюджет игры — до 400 мешей и 250 вызовов отрисовки; у образца 270 мешей и 137 вызовов.
- **Автопроверка** `node portal/tools/check-game.js --self` прогоняет игру в Chromium без окна. Проверки:
  - загрузка и картинка;
  - геймпад, клавиатура и стартовое нажатие;
  - случайная игра и каждый пресет;
  - ручки, перезапуск и конец партии;
  - бюджет отрисовки, физика, ловля ошибок.
- **Промпт для Qwen** (`portal/ai/game-prompt.md`) состоит из следующих частей:
  - роль: «ученик решает, программист исполняет, свои решения записывает в `notes`»;
  - формат ответа, контракт и API `lab`;
  - шпаргалка Babylon, сверенная с типами;
  - запреты и требования к игре;
  - чек-лист;
  - образец целиком.

  Около 11 тысяч токенов (с двумя образцами и правилами стрельбы и ближнего удара — около 28 тысяч, потолок поднят до 30 тысяч 17.10.2026). Для Claude Sonnet 5 (основная модель курса; Qwen автор не использует, 17.10.2026) свой системный промпт — `portal/ai/claude-prompt.md`, около 16,6 тысячи знаков, и **один** образец. У игры ученика это донор урока, у игры класса — образец каркаса связки: арена — «Ночной лабиринт», ловля — «Ледолом», бег — «Шаг в такт», вид сбоку — «Тур над Хаджохом», тир — «НЛО». Весь промпт — 39–51 тысяча знаков вместо 96 тысяч. Каждое правило сказано один раз. В промпте:
- план игры комментарием;
- «план — обещание», нет доминирующей стратегии, кривая партии, бесконечный мир;
- камера и `lab.hero`;
- три слоя яркости;
- шесть шагов ощущения действия — из разбора видео о выстреле и ударе;
- четыре партии в уме: новичок, пассивный, торопыга, мастер.

Причина: разбор «Козла Фишта». Прежний промпт под Qwen на две трети состоял из двух образцов, и Sonnet копировал их неподвижное поле. Каркас игры ученика выбирает продюсер (поле `frame`): если замысел ушёл из жанра донора, программист получает образец этого каркаса, иначе — донора урока.

**Бот-плейтестер** (17.10.2026). После каждой сборки игры класса бот сам играет три партии в одном мире: пассивный, торопыга и новичок. Отчёт сохраняется у версии. Бот находит:
- героя за кадром;
- доминирующую стратегию «мять A» или выгодное бездействие;
- пустое время;
- слишком раннюю смерть.

На «Козле Фишта» бот нашёл обе беды сам: «мять A» дало 455 очков против 65, герой был за кадром 76 % времени. По отчёту учитель жмёт «Пусть программист поправит по отчёту». Правка идёт **кусками** (решение автора 17.10.2026): модель присылает только заменяемые куски «НАЙТИ → ЗАМЕНИТЬ», портал вставляет их сам, и ответ в разы короче всей игры. Так же кусками идут правка ученика в мастерской и починка упавшей игры. Если куски дважды не легли в код или сломали синтаксис, портал просит ту же правку целиком: дороже, но правка не теряется. Бот проверяет новую версию снова; если стало хуже, есть «↩ Вернуть». Шаблоны сообщений ученика: новая игра, одна правка, исправление ошибки.

## Стандарты (решения автора курса)

- **Игра, а не иллюстрация.** Игра ученика к концу занятия понятна за 10 секунд, у неё есть цель, нарастание, проигрыш или рекорд и повод сыграть ещё раз. Перезапуск быстрее секунды, 2–3 минуты интересной игры, понятие занятия крутится ручками. Главный тест: плейтестер сам нажимает «ещё раз».
- **Механику берём, мир свой.** Своё название, герой и стиль, подпись «по мотивам механики …». Чужие имена, персонажи, графика, музыка и логотипы не используются. Из игр 18+ берём только механику, без жестокости.
- **Ученики максимально креативят сами** (16.10.2026). Не меньше 70% занятия — своя игра. Готовые прототипы учителя — только короткий вход на 1–2 минуты, теорию разбираем на игре ученика.
- **Игра ученика — яркая детальная лоуполи 3D-игра** (16.10.2026), страница HTML от Qwen в чате. Замысел собирается в Фабрике (свои слова + карты Донор / Твист / Мир), промпт ИГРА уходит Qwen.
- **Картинка в каждом задании для chat.qwen.ai** (решение автора 18.10.2026). Одинаковое задание дало у Qwen3.8-Max игры без багов, но невзрачные, а у Qwen3.8-Omni-Flash — яркие, но с ошибками вида «pick is not defined». Причина — в задании о картинке была одна фраза «яркую lowpoly». Теперь «ярко» расписано по пунктам в разделе `look` файла `portal/ai/chat-prompt.md`: палитра, небо и туман, свет и тень, свечение, декор не меньше 30 объектов, частицы, тряска камеры, шрифт экранов, бережность к слабым компьютерам. Правило для всех уроков, нынешних и будущих: раздел вставляют не уроки, а общая сборка текстов для чата в `lib/ai.js` — `chatTask` (любое задание на новую игру: игра класса, своя игра ученика) и `chatMove` (перенос в новый чат); правка, починка, договор и просьба из конструктора несут строку «картинку не упрощай». Любой урок с `programmer: 'chat'` получает это сам; новый вид сообщения для чата пишется в `chat-prompt.md` и собирается через `chatTask` или со строкой «картинку не упрощай». Следит `e2e-qwen-chat.js`: без раздела «Картинка» в задании, игре класса и переносе проверка падает. Менять, что значит «ярко», — только в разделе `look`.
- **Геймпад в каждой игре с первой версии.** Меню и подсказки показывают кнопки геймпада, если он подключён; подсказки переключаются по последнему устройству ввода.
- **Кубик предлагает, автор решает.** Кубик со случайным вариантом у каждого поля для идеи, решения и промпта. Нетронутые варианты помечаются [кубик], и учитель видит, где ученик думал сам. Колоды кубиков зависят от донора, чтобы кубик не приносил правило из другой игры.
- **Ручки геймдизайнера (Tab)** в каждой игре: все важные числа и пресеты «Новичок» и «Как задумано».
- **Видно = правда.** Всё, что наносит урон, выглядит ровно таким, какой урон наносит; опасность видна заранее.
- **Стреляющий герой** (17.10.2026, по видео автора). Выстрел собирается из восьми шагов: заряд, крупное светящееся ядро, огненный след, отдача, искры сквозь врага, вспышка и отлёт врага, «вжух» и «бум», последствия (горит, падает, оставляет след) и очки, которые крупнеют с серией. Босс стреляет по-своему, путь его снарядов виден, пока он заряжается. Правила — в skill `lab3d-igra` (`pravila.md`), образец — «НЛО в станице».
- **Ближний удар** (17.10.2026, по видео автора): видимая дуга удара и попадание ровно по ней, вспышка врага на 2–4 кадра, резкий звук в кадр попадания, частицы по направлению удара, отбрасывание врага и лёгкий отскок героя, тряска и стоп-кадр, смерть — враг лопается кусочками. Правила для ИИ — там же.
- **Понятность** (решение автора, 17.10.2026). Игрок ни разу не гадает: направление выстрела или удара показано и совпадает с тем, куда действие уходит; размер попадания равен видимому; опасное отличается цветом и предупреждено; жизни, очки и заряд видны в HUD; твист понятен без текста за 10 секунд. Правило — в skill `lab3d-igra` (`pravila.md`), раздел «Понятность».
- **Нажатие, которым запущена партия, не засчитывается в игре.**
- **ИИ исполняет, ученик решает.** Сначала три решения (чувство, честность, выбор), потом промпт по формуле «ИГРА» (Идея и чувство, Глагол и кнопки, Правила, Атмосфера).
- **Продюсер читает замысел до программиста:** противоречия, решения без кнопки, цели вместо решений, лишние механики, «кубик из другой игры», узнаётся ли донор, есть ли социальный крючок, нет ли чужих имён и персонажей, не заглушает ли наказание главную механику.
- **«Пусть поправит продюсер»** (решение автора 17.10.2026, урок 1). Кнопка в шаге продюсера: по своему разбору (находки, развилки и выбор автора) продюсер переписывает четыре поля ИГРА. Ученик видит «было → стало» и сам решает, принять правку или оставить как было; принятые поля можно потом поправить своими словами. Промпт — раздел `fix` в `portal/ai/producer-prompt.md`.
- **Связка от ИИ для колоды безумных идей** (решение автора 17.10.2026, урок 1). Карты по-прежнему тянутся случайно: абсурд и голоса «перетянуть» — это вау. Когда четыре карты на столе, текстовая модель за несколько секунд сводит их в одну игру: фраза игры, главный цикл, поворот × действие, главный смешной момент. Связка выходит на проектор и в панель учителя; учитель принимает её, просит другую или правит руками («✎ Править»; без ключа ИИ — «✎ Написать самому»). Принятую связку видят ученики под картами, и она уходит программисту вместе с картами. Перетянули карту — связка сбрасывается. Для урока это живой пример работы геймдизайнера: свести ограничения в одну игру. Промпт — `portal/ai/link-prompt.md`.
- **Связка 2.0 после «Козла Фишта»** (17.10.2026). Игра класса по связке прошла все автопроверки, но не игралась: связка от qwen-flash предложила точные прыжки по 3D-плитам при неподвижной камере, риск без очков и цель «продержаться три минуты». Теперь промпт связки знает формат «Лаб3D» (поле целиком, камеры, кнопки, 1–3 минуты, проектор), выбирает один из пяти надёжных каркасов (арена, ловля, бег навстречу, вид сбоку, тир) и переводит на них трудные действия, перечисляет, чего ИИ не соберёт, платит за риск очками и проверяет себя четырьмя партиями в уме (новичок, пассивный, торопыга, мастер). Полей девять: фраза, каркас и камера, кнопки, цикл, риск и очки, угрозы, нарастание, поворот × действие, смешной момент. Пишет связку модель программиста (или `linkModel`). Разбор — `analysis/kozel-fishta-razbor.md` в файлах проекта.
- **Плейтест после каждой игры:** рекорд, ощущения, эксперимент с ручкой, что поменять. Отзыв учителя с одним понятием геймдизайна и вопросом.
- **Всё интерактивно** (16.10.2026). Вопросы, квизы и задания — мини-игры или живые артефакты с кнопками, геймпадом, таймером, очками, звуком и мгновенным отзывом, а не текст со строкой ответа. Итог присылается кнопкой «Скопировать результат».
- **Чекпоинты открывает учитель,** ученики идут синхронно.

## Портал, срез 2 «Играем вместе» (17.10.2026)

- **Аркада класса — сама, с первой версии.** Каждая собранная игра ученика сразу попадает в аркаду класса (`/arcade`, вкладка «Аркада» у учителя). На карточке:
  - название и автор-ник, подпись «по мотивам механики …»;
  - «Что решил я» — три решения;
  - текущая версия и рекорд класса.

  Автор может скрыть игру. Скрытая игра остаётся у автора в личной аркаде и у учителя.
- **Чекпоинт «Играем вместе» в уроке 1** (15 минут, между Мастерской и Открытием):

  - шаг `playtest` — отзыв на игру соседа;
  - текст-итог «Доминирующая стратегия».
- **Сосед — по кругу:** следующий по алфавиту автор с игрой этого урока. Кнопка «Следующая игра по кругу» и выбор из аркады — для тех, кто хочет другую.
- **Рекорд автора** — лучший счёт автора в своей игре. Его видно рядом со своим и рекордом класса. Побил — портал предлагает бросить вызов.
- **Вызов «побей мой мир»** — код из 6 знаков и ссылка `/arcade?ch=КОД`: игра, версия и зерно партии. У вызова своя таблица.
- **Вызов в любой игре урока** (решение автора 17.10.2026, урок 1). Кнопка «⚔ Вызов: побей мой мир» стоит под донором, игрой класса, игрой учителя и игрой ученика. Вызов хранит игру, версию, зерно и изменённые ручки.
  - **Доска вызовов класса** над шагами урока и в аркаде. Новый вызов появляется у всех сам, копировать код не нужно. Кого обогнали, тот получает «Отыграться» — цепочка реванша.
  - **Призрак соперника.** Оболочка пишет счёт по секундам (`tele.line`). В вызове под счётом видно очки лидера на той же секунде: «ты впереди на 300».
  - **Мир дня** — вкладка проектора. Учитель одной кнопкой даёт всему классу один мир донора или игры класса, таблица растёт на проекторе. Концепция для разговора: одно зерно — честное сравнение, где мастерство, а где удача.
  - Ссылка работает на любом компьютере класса после входа по коду класса.
  - Код сделан коротким, чтобы его можно было сказать вслух или написать на доске.
- **Плейтест тап-карточкой:** одна-две эмоции кнопками и «Нравится / Хочется / А что если» с кубиком. Анкеты нет.
- **Открытие плейтеста считается только по чужим партиям:**
  - сколько партий и игроков, сколько раз нажали «ещё раз»;
  - какую кнопку держали дольше всего;

  Свои партии автора не считаются: автор знает игру и играет иначе.

## Урок 1: вау-старт и спрятанная механика (17.10.2026)

Чекпоинты 1–2 вернулись к логике версии 1 и стали процедурными (решение автора, 17.10.2026).

- **Чекпоинт 1 «Вау-старт».** Учитель при классе тянет карты колоды безумных идей (герой, действие, место, поворот) и запускает сборку. Пока ИИ собирает игру (10 минут и дольше), ученики играют в донор «НЛО в станице» и отвечают «Что здесь цепляет?» (решение автора 17.10.2026). Потом учитель раздаёт игру класса, все играют и отвечают на плейтест.
- **Игра класса — своя игра только из четырёх карт** (решение автора 17.10.2026, заменяет «колода «действие» привязана к донору»). Первая демонстрация того, как ИИ из четырёх карт собирает простую, яркую и смешную игру, поэтому она не связана со Space Invaders: колоды «действие» и «поворот» общие для любого жанра, в задании программисту нет донора, образцы в системном промпте показывают только устройство кода, их жанр брать запрещено. Формула — герой × действие × место × поворот.
- **Стандарт картинки в промпте** (17.10.2026): цветная палитра и небо, пол не одной плоскостью, три вида деталей места, герой с глазами и анимацией, свечение важного, частицы и звук на каждое событие. Проверка — пункт 6 чек-листа программиста. Повод — серая и бедная игра класса на первом прохождении.
- **Спрятанная механика закладывается в код с первой сборки.** Программист получает вместе с картами спрятанную механику из колоды спрятанных механик урока: ручка `secret`, пресет «Без спрятанной механики», скрытый счётчик `_secret` (его моменты уходят в телеметрию `marks`). Спрятанные механики не зависят от жанра. **В уроке 1 — только заметные нагнетатели двойной силы** (решение автора, 17.10.2026: тайных помощников за 2–3 партии не почувствовать): злой финал раунда, незаметный разгон, сердцебиение, время замирает на волоске, тройные очки за риск. Помощники (поддавки на последней жизни, доворот, прощение краем, прощение в начале) — для урока о сложности и честности.
- **Кто выбирает спрятанную механику** (решение автора): кубик тянет случайную, учитель видит её в панели и может тайно заменить до сборки.
- **Чекпоинт 2 «Спрятанная механика»** строится на игре из чекпоинта 1 (решение автора, 17.10.2026): **слепой тест А/Б** (шаг `abtest`: две одинаковые на вид копии, в одной спрятанная механика выключена, ученик играет по партии и голосует, где напряжённее), «Найди спрятанную механику» (настоящая, две чужие и ловушка — поворот с карты), раскрытие: в какой копии была спрятанная механика и почувствовал ли её ученик, цифры копий (счёт, длина партии, урон, срабатывания) и полоска партии с моментами спрятанной механики. ## Урок 1: колода безумных идей 2.0 (18.10.2026)

Задача автора: карты смешные для школьников, но каждая несёт яркое решение геймдизайнера; комбинаторики больше. Решение автора — пятая колода «Угроза».

- **Пять колод вместо четырёх:** герой (50) × действие (40) × место (44) × угроза (41) × поворот (40) — около 144 млн сочетаний вместо 1,6 млн. Формула — «Герой × действие × место × угроза × поворот», заменяет формулу из четырёх карт.
- **Карта = смешное имя + решение.** У героя, места и угрозы карта пишется «имя — особенность» (`parts: true`): «Пельмень-беглец — чем дольше бежит, тем горячее и быстрее», «на Луне — всё прыгает далеко и падает медленно», «Бабушка с тапком — кидает тапок туда, где ты будешь». Особенность героя — его механика (свойство движения или кнопка B), места — правило поля, угрозы — поведение. На проекторе, у учителя и у ученика имя крупно, особенность строкой ниже (`Games.cardFace`), барабан крутит имена.
- **Угроза — главный источник давления.** Каждая карта — свой тип противника: гонится стаей, бьёт на упреждение, «замри», пикирует на видимую тень, крадёт собранное, делится от удара, повторяет твой путь, тянет к себе, поднимается снизу. Разбор «Козла Фишта» показал, что без понятной угрозы игра класса не играется — теперь угроза приходит с карты.
- **Действия — глагол с давлением** («…, пока не…», «чтобы ни одна не упала»): добавлены жонглирование, тарелки на шестах, «тащит добычу на базу», «крадётся мимо прожекторов», «перебегает поток», кроты, фотоохота, взмахи крыльями. Убраны действия, которые ИИ не соберёт (физика стопок заменена на «ставит этажи башни точно друг на друга»).
- **Повороты — правило с двумя сторонами** (помеха и оружие): «препятствия можно толкать во врагов», «очки копятся в мешке: донёс до базы — твои», «время идёт, только когда ты двигаешься», «трижды задетый враг переходит на твою сторону». Повороты не повторяют спрятанные механики урока: убран «время замедляется, когда опасность рядом» (совпадал со спрятанной механикой «Время замирает на волоске» и ломал ловушку в «Найди спрятанную механику»), «опасность сначала слышно» (только в наушниках).
- **Любая карта сочетается с любой:** особенности не привязаны к жанру, каркасы в промпте связки описаны глаголами, а не списком карт, поэтому колоды можно менять, не трогая промпт.
- **Связка и программист** получают карту угрозы: в связке поле «Угрозы» начинается с угрозы с карты, в задании программисту — строка «Угроза» и правило «ведёт себя ровно как после тире, атака видна заранее» (`portal/ai/link-prompt.md`, шаблон `user:wow` в `portal/ai/game-prompt.md`).
- **Квиз «Чьё это решение?»** берёт имя и особенность раздельно: «Нарисовать героя: {heroName}» — художник, «Решить, что у героя есть особенность: {heroTrait}» — геймдизайнер, «Запрограммировать угрозу «{threatName}»: {threatTrait}» — программист. Название игры класса — имена карт без особенностей.
- **Проверка:** `e2e-portal.js` считает карты по сценарию урока, проверяет особенность на карте героя и что карта угрозы с особенностью ушла программисту.
- **Версия 2 урока 1** (Qwen в чате) берёт колоды из первой версии сама; в её сценарии учителя тоже «пять безумных карт».

## Урок 1: спрятанная механика, которую видно (18.10.2026)

Автор: многие спрятанные механики урока 1 даже взрослому не рассмотреть. Разбор и предложение — документ «Урок 1: спрятанная механика, которую видно» (https://claude.ai/code/artifact/1a23c247-3b15-49cc-874c-1fa0613dac7f), автор принял все четыре пункта.

- **Правило: спрятанная механика прячет причину, а не эффект.** Эффект виден сразу и крупно: первое срабатывание не позже 15-й секунды, не реже 4 раз в минуту, главное число меняется в 2–3 раза, картинка и звук рядом с героем. Правило игра не объявляет.
- **У каждой спрятанной механики своя «база»** (`base` в колоде `wow.secrets`): что из общих правил системного промпта в этой игре делает только спрятанная механика. Программист получает её строкой «В этой игре только спрятанная механика делает вот что…», поэтому копия «Без спрятанной механики» больше не содержит спрятанную механику. Системный промпт не менялся — кэш цел.
- **Пять спрятанных механик переписаны:** «Последние враги злятся» (волны по 6–10, последние 1–2 краснеют и носятся в 2,5 раза быстрее), «Игра незаметно разгоняется» (с 6-й секунды +20% каждые 6 с, до ×3), сердцебиение — бас и красная виньетка, без флага «только в наушниках», замедление у промаха (ближе 1,5 м — 0,7 с ×4, серый мир), золотое кольцо риска (×3 очков ближе 3 м). Ручка `secret` теперь 0–2: 0 — выключен, 1 — как задумано, 2 — вдвое сильнее.
- **Бот сравнивает копии** (игры на оболочке Лаб3D; в игры из чата Qwen бот не играет). К трём партиям бота добавилась партия «Новичок без спрятанной механики» с тем же зерном и нажатиями (`playtest({compare:{knob}})` → `report.off`). Сервер считает спрятанную механику слабой (`secretWeak`), если первое срабатывание позже 15 с, реже 4 в минуту или копии почти не различаются по метрике спрятанной механики (`bot` в колоде), и один раз сам отдаёт программисту правку.
- **Лупа в оболочке.** Сообщение `reveal` зажигает значок «🔍 Спрятанная механика: …», который вспыхивает на каждом `count('_secret')` (в обеих оболочках Лаб3D — Babylon и three.js — и в мосте HTML-игр). Новые шаги после «Найди спрятанную механику»: «Посмотри на спрятанную механику» (лупа и кнопки силы 0 · 1 · 2, партии не идут в рекорды) и «Что менялось, когда горела лупа?».
- **«Спрятанная механика рядом» на проекторе.** Вкладка показывает две копии игры класса: слева без спрятанной механики, справа с лупой. В игре на оболочке Лаб3D бот-новичок играет обе 60 секунд в настоящем времени одним зерном (`botShow`), копии расходятся только из-за спрятанной механики. В игру-страницу из чата Qwen (версия 2) бот не играет: проектор говорит об этом, и копии играют вручную, лупа горит так же. Название спрятанной механики появляется после запуска.
- **Минуты: 85 + 20 + 75.** «Игра класса и спрятанная механика» 27 → 32 минуты, «Турнир и финал» 20 → 15. Если спрятанную механику почувствовали меньше половины, учитель обязательно показывает вкладку «Спрятанная механика рядом».
- **Фабрика:** подсказка твиста — «Твист игра объявляет, спрятанная механика — нет», поле «Спрятанная механика: чем ты тайно усилишь чувство».
- **Спрятанная механика по шагам для Qwen** (Андрей: Qwen собирал спрятанную механику невнятно). У каждой спрятанной механики поле `howto`: переменные, что считать каждый кадр, как сила `cfg.secret` от 0 до 2 меняет эффект, где вызывать `portal.count('_secret')` и «проверь себя» на первые 15–20 секунд. В задание Qwen уходит спрятанная механика, выбранная у учителя (кубик или тайная замена), с её `howto`; у своей игры ученика — карта спрятанной механики из Фабрики.
- **Одна спрятанная механика игры класса** (решение автора 18.10.2026): «Игра незаметно разгоняется» для всех классов (`wow.classSecret` в `urok-01.js`). Кубика и тайной замены у учителя нет, сервер замену не принимает. Почему разгон: Qwen собирает его надёжно (одна переменная темпа), он есть в любой связке карт, виден в копиях А и Б, на вкладке «Спрятанная механика рядом» и на кривой партии, и это спрятанная механика Нисикадо в общем виде. Задание Qwen для него расписано по каркасам игры (стрельба, уворот, сбор, стройка). Остальные четыре спрятанные механики остаются чужими вариантами в «Найди спрятанную механику» и картой спрятанной механики своей игры в Фабрике; кандидаты в другие уроки: риск — награда и риск, замедление — «Сочность», сердцебиение — «Звук».
- **Меню игр из чата Qwen.** Экран конца партии закрывается по Start, Enter или R (A и пробел — нет: ими только что играли). Подписи кнопок — парой `keys-only` / `pad-only`, мост `portal.js` показывает подписи геймпада, когда он подключён или нажата его кнопка. Если игра забыла Start на экране конца, мост нажимает за неё Enter, потом R.
- **Проверка:** `e2e-portal.js` проверяет строку бота без спрятанной механики, лупу (значок, счёт, кнопка «Спрятанная механика 0») и вкладку «Спрятанная механика рядом».

Скрытый счётчик `_secret` считает повороты, где характер повёл волка не туда, куда ведёт простая погоня.
- **Телеметрия динамики:** окружения (волки с двух противоположных сторон идут на тебя), хвост (волки сбились в стаю), засада у факела, прогнанные волки. В прогонах ботом со спрятанной механикой окружений в несколько раз больше, чем без неё (6–17 против 1–2 за две минуты).
- **«Видно = правда»:** у каждого волка свой цвет; факел мигает белым перед концом; дверь дольмена светится цветом волка, который выйдет следующим; при смене погони и разбега все волки разворачиваются и звучит сигнал; пресет «Цели видно» рисует крестик цели каждого волка.
- **Чекпоинт «Спрятанная механика»:** предсказание динамики для волков с одним правилом → партия «одно правило» → сравнение предсказания с телеметрией → «Найди спрятанную механику» (ловушка — «волки быстрее») со сравнением окружений и хвоста → история Иватани и MDA, восемь удовольствий Леблана → квиз «Угадай охотника по следу» → сортировщик «Механика, динамика или эстетика?».
- **Фабрика MDA:** один донор, колоды под лабиринт с охотниками; поля «Охотники и их характеры», «Сила», «Главное удовольствие», «Предскажи динамику», на продвинутом — «Перекрась чувство», на боссе — сломанное правило. Предсказание автора видно в плейтесте рядом с открытием плейтеста.
- **Дуэль** в «Играем вместе»: второй игрок ведёт Вожака (ручка `vs`, пресет «Вдвоём»).
- **Новые типы шагов:** `trace` — квиз по следу охотника в лабиринте на холсте; `predict` — предсказание динамики против счётчиков шага `play`; у `playtest` — поле `predict`. Описано в `portal/README.md`.
- **Образец урока для программиста** — «Ночной лабиринт» (`sample` сценария, промпт около 28,1 тысячи токенов). Дуэль — через поле `duo` оболочки 0.2 (ручка `vs`).

## Урок 8: мини-джем «Одна кнопка» (17.10.2026)

## Урок 8: донор на three.js и разбор жанра (этап C8, 18.10.2026)

«Башня до неба» переписана на оболочку «Лаб3D» 1.0 (`engine: 'three'`), без Babylon. Спрятанная механика (окно «идеально» и рост плиты за серию), ручки `size`, `speed`, `speedup`, `maxSpeed`, `range`, `thick`, `snap`, `grow`, `growBy`, `lives`, `secret`, `duel`, пресеты «Новичок», «Без спрятанной механики», «Вдвоём», «Ветер», счётчики `идеально`, `плиты`, `_secret` и `GAME.place`, `state.towers`, `T.mv`, `T.top` прежние: сценарий урока и e2e на них опираются. Новые ручки: `patience` (проездов до срыва плиты), `cue` (тик-тик перед точкой), `sway` (качание башни), `goal` (лента финиша вдвоём).

Разбор жанра «башни на одну кнопку и тайминг»: что взяли.

| Игра | Самый интересный момент | Что взяли в «Башню до неба» |
| --- | --- | --- |
| Stack (Ketchapp, 2016) | Плиты едут то по одной оси, то по другой; на «идеально» по краю плиты расходится светлая волна и звучит нота выше; длинная серия возвращает ширину; цвет плит и неба плывёт с высотой | Всё это: оси по очереди, волна-рамка по краю (с серией — две и три волны), пентатоника вверх, рост плиты на глазах, оттенок слоёв меняется с высотой. Короткий наезд камеры на каждое «идеально». В конце партии камера отъезжает и показывает всю башню целиком |
| Tower Bloxx (2005) | Неточный этаж раскачивает башню, точный её успокаивает | Неточная плита качает башню пружиной (ручка `sway`), «идеально» гасит качание. Качание только для вида: на попадание не влияет |
| Tricky Towers (2016) | Гонка башен до финишной линии в небе | Вдвоём — светящаяся лента финиша на высоте 40 плит (ручка `goal`): кто первым до неё дотянулся, тот победил; без ленты побеждает тот, чья башня выше |
| Rhythm Heaven (2006), Canabalt (2009) | Звук подсказывает момент раньше картинки; одна кнопка, вся глубина — в тайминге | Два тихих щелчка за полсекунды и четверть секунды до того, как плита встанет над башней (ручка `cue`): нажатие ложится на третью долю. Это понятие модуля «звук предупреждает раньше картинки» прямо в доноре |
| Doodle Jump (2009), Flappy Bird (2013) | Рекорд виден на поле; рубежи высоты дают маленькие награды | Золотая лента рекорда на высоте лучшей башни этого захода в игру, «Новый рекорд!» с фанфарой. Рубежи: «Выше сакли», «Выше орла», «Выше облаков», «Закат», «Звёзды», «Почти космос», «До неба» |
| Jenga, физические башни | Обломки падают и остаются лежать | Отрезки кувыркаются в сторону промаха и ложатся на выступ башни, подножие или землю, с пылью и глухим стуком, и остаются лежать грудой у подножия |

«Видно = правда»: пока плита едет, красным подсвечено ровно то, что свисает за край башни и отрежется. Со спрятанной механикой красного нет, когда промах меньше окна «идеально», поэтому подсветка не врёт ни с окном, ни без него. Бездействие наказано: плита, которая проехала туда и обратно и не дождалась нажатия, мигает красным на последнем проезде и срывается (ручка `patience`, у «Новичка» — четыре проезда).

Графика и ощущение: небо по высоте башни — день, золотой час, закат, сумерки, ночь со звёздами и луной, почти космос; солнце садится, тени длиннеют. Плато Лаго-Наки с аулом, пихтами, камнями и снежными горами на горизонте, облака на высоте 12–17 м, которые башня пробивает, орёл кружит над плато. Подножие — каменная плита со стоячими камнями, как у дольмена. Все плиты башни — одна пачка копий (InstancedMesh), отрезки у подножия — вторая: башня в 400 плит рисуется за пару вызовов, у всей игры около 60.

Бот-плейтестер: бездействие падает на 19-й секунде, «мять A» — на 3-й без очков, случайная игра — на 5-й. Замечание «слишком сложно для новичка» оставлено сознательно: в игре на тайминг случайное нажатие почти всегда мимо, а настоящий новичок жмёт, когда плита над башней (для него пресет «Новичок»).

Не взяли: маятник крана из Tower Bloxx (вторая механика рядом с главной), физическое обрушение башни (сломало бы честность «что видно красным, то и отрежется»).

## Быстрая проверка в две ступени (18.10.2026, решение автора)

- **Почему.** Полная проверка шла 31 минуту и запускалась почти после каждой задачи. Замер: проверка портала 23 минуты (прогон с подставным ИИ 15,7, демо 7,5), игр 7,4, чата Qwen 9 секунд. Без видеокарты игры рисуются по 2–9 кадров в секунду, игровое время идёт в 3–10 раз медленнее настоящего, и проверка в основном ждёт, пока игра «поиграет».
- **Ступень 1, после задачи:** `node portal/tools/check.js` сам выбирает проверки по изменённым файлам: одна игра и уроки, где она донор; `e2e-portal.js --only=N` для сценария урока N; демо-прогон, только если трогали ИИ, сервер или сценарий; чат Qwen для портала. Документы и skills не проверяются. После `git pull --rebase` — `check.js --since=<коммит до pull>`.
- **Ступень 2, полная:** `node portal/tools/check.js --full` — перед меткой урока, перед прохождением, после больших правок сервера и оболочки. Каждую ночь в 02:00 по Москве её гоняет GitHub Actions (`.github/workflows/nochnaya-proverka.yml`).
- **Сами проверки быстрее.** Игры в проверках рисуются в половину разрешения (`LAB_LOWRES`, снимки `check-game.js` — в полном), квизы-загадки просят поиграть секунду, паузы квизов короче (`LAB_FAST`), сортировщики ждут смены карточки, а не паузу. `check-game.js` проверяет по 3 игры одновременно и пропускает игры, которые не менялись с последней зелёной проверки (`--all` — все). Ученики ничего из этого не видят.
- **Правило для e2e:** ждать по часам игры (`window.__lab.lab.t`) или по состоянию страницы, а не `sleep()`: под нагрузкой настенные секунды врут.
- Не делаем: два прогона портала одновременно — под нагрузкой падают ожидания «Играем вместе».
- **Почему падало «Играем вместе» (найдено 19.10.2026).** Без видеокарты графику всех окон рисует один процесс SwiftShader. Игры, которые просто стоят в меню или на экране конца партии, рисовали 60 кадров в секунду со свечением и занимали все четыре ядра (процесс GPU — 327 % процессора). Новая игра в рамке у соседки или в окне вызова грузилась 25–37 секунд, а e2e ждал 30. Падало и до переписывания доноров. Исправлено: с `LAB_LOWRES` (только в проверках) оболочка рисует меню, паузу и конец партии 5 раз в секунду, загрузка — 9–14 секунд; `gameFrame` в e2e опрашивает рамку из проверки до 60 секунд и при неудаче пишет, какие рамки были и в каком состоянии.

## Термин «спрятанная механика» вместо «секрет» (18.10.2026, решение автора)

3. Ремейк-донор учителя: название, мир, ручки, пресеты, что показывает.
4. Своя игра ученика: Фабрика (карты и колоды), три уровня задания, формат задания для ИИ.
5. Играем вместе: формат, социальный крючок.
6. Плейтест: вопросы, что ищет телеметрия.
7. Квиз или другая проверка.
8. Достижения и линза урока.
9. Правки, появившиеся при прохождении (со ссылками на задачи).
10. Что нужно добавить в портал: типы шагов, движок, Лаб3D.

## Наработки версии 1 (уроки 1–2, прототипы 3 и 5)

Подробности — в `archive/v1/`. Всё ниже учтено в программе 2.0.

### Удачные приёмы интерактива

- Колода безумных идей (герой + действие + место + поворот) как вау-старт.
- «Найди, где ИИ своевольничал»: в игре есть механика, которой не было в промпте. Ловушка — ученик называет механики, которые в промпте были. Урок «проверяй, а не верь».
- Квиз «Чьё это решение?» (дизайнер / программист / художник).
- Развилки продюсера кнопками вместо переписывания идеи за ученика; продюсер — отдельный экран: находки + развилки.
- Телеметрия кнопок → «открытие плейтеста»: доля времени с зажатой кнопкой показывает доминирующую стратегию.
- Личная аркада: игры, достижения, XP, линза, открытие дня, план версии 2.
- Квиз-мини-игра с раундами («Игра или не игра?» ◀ ▶ и сортировщик по 8 лоткам): таймер, серия, разбор после каждой карты.
- Правило ученика встраивается в общую игру класса как новый пресет → достижение «Автор правила».
- Тап-карточка плейтеста вместо анкеты.
- Фабрика MDA (урок 3): предсказание динамики, телеметрия динамик после партии, миссия «перекрась чувство» одной картой.
- «Лаборатория прыжка» (урок 5): слепой турнир по одной ручке, 11 ручек прыжка.

### Открытия ученика-тестировщика

- Метки до удара шумят → решение «сделать тише», а не «убрать».
- Невидимая волна-гребень → правило «видно = правда».
- Тормоз держался почти всегда → доминирующая стратегия, тормозу нужна цена. Пресет «Новичок» ощущался лучше → базовая сложность первой игры была завышена.
- Решённая игра (крестики-нолики 3×3) скучна: исход известен.
- В квизе слабее всего ресурсы (жизни, нагрев тормоза) → у лотков нужны примеры и подсказка после ошибки.
- Замысел почти из одних кубиков спорит сам с собой (кнопка без способности, бот без бота).
- Смерть от стены заглушила главное правило змейки → «наказание не должно заглушать главную механику».

### Платформа версии 1

- Node.js 18+, без зависимостей, локально на компьютере учителя; ученики в той же сети.
- ИИ через OpenAI-совместимый API: провайдер provod.ai (https://api.provod.ai/v1, оплата в рублях; бонусный баланс открывает не все модели). Код по умолчанию — anthropic/claude-sonnet-5 (решение автора 17.10.2026; temperature ему не передаётся), запасной — qwen3.7-max; текст (продюсер) — тоже anthropic/claude-sonnet-5 с 17.10.2026. Оценка для 2D-игр: 200–450 ₽ на класс из 14 за урок.
- Демо-режим без ключа для репетиции.
