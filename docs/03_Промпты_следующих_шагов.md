# Промпты следующих шагов

Готовые задания для чатов Claude после среза 1 портала (17.10.2026). Подходят и для других аккаунтов Claude. Каждый промпт самодостаточен: Claude прочитает репозиторий, сделает работу, проверит её в браузере и отправит в `main`.

## Перед началом

1. Откройте Claude Code (в браузере, на claude.ai/code или в приложении) и подключите GitHub-репозиторий `mentalart/GameLab` с правом записи. У аккаунта должен быть доступ к репозиторию на GitHub: владелец добавляет его в Settings → Collaborators.
2. Один промпт — один чат. Следующий промпт запускайте, когда предыдущий отправлен в `main`.
3. Если Claude спрашивает про ключ ИИ — не давайте его в чат. Для проверок есть демо-режим и подставной ИИ (`portal/tools/mock-ai.js`); настоящий ключ живёт только в `portal/config.json` на вашем компьютере или сервере.

Порядок: срез 2 → срез 3 → урок 1 (прохождение) → правки урока 1 → сборка урока 2 → … После модуля 1 (уроки 1–4) — пробный хостинг. В промптах 3–5 замените N на номер урока (`урок-0N` → `урок-02`).

## 1. Срез 2 портала: «Играем вместе» (готов 17.10.2026)

```text
Ты — разработчик портала курса геймдизайна «Лаборатория игр» (репозиторий mentalart/GameLab). Сначала прочитай CLAUDE.md, docs/01_Журнал_курса.md, portal/README.md и portal/engine/README.md, затем просмотри portal/server.js, portal/public/student.js, portal/lessons/urok-01.js. Срез 1 готов: вход по коду класса, урок по чекпоинтам, Фабрика с кубиками, продюсер, сборка игры ИИ с автопочинкой, мастерская, панель учителя, заметки автора, журнал генераций.

Задача — срез 2 «Играем вместе» (блок занятия «Играем вместе», 15 минут, по программе docs/02_Программа_курса.md, раздел «Устройство занятия», «Ритуалы курса» и занятие 1):
1. Аркада класса: каждая собранная игра ученика попадает в аркаду класса (название, автор-ник, донор, подпись «Что решил я» из трёх решений, текущая версия, рекорд класса). Аркада — отдельная страница /arcade для учеников класса и вкладка у учителя. Автор может скрыть игру из аркады.
2. Новый тип шага `arcade` («Сыграй в игру соседа и побей рекорд автора»): ученик получает игру одноклассника (по кругу или на выбор), играет в рамке-песочнице, видит рекорд автора и свой; рекорды уходят в таблицу рекордов этой игры.
3. Вызов на зерне: из экрана конца партии и из аркады — ссылка/код «побей мой мир» (игра + версия + seed); /play/<id>/<n> должен принимать ?seed= и передавать его в оболочку (в lab.js уже есть параметр seed и сообщение seed).
4. Новый тип шага `playtest`: тап-карточка плейтеста вместо анкеты — эмоции кнопками, «Нравится / Хочется / А что если» с кубиком, и телеметрия автора: оболочка присылает в сообщении over поле tele (hold, presses, custom). Покажи автору его «открытие плейтеста»: какую кнопку держали дольше всего (доминирующая стратегия), сколько раз нажали «ещё раз» (сообщение again), сколько партий сыграли чужие игроки.
5. Отзыв учителя: в панели учителя у каждого ученика поле отзыва «одно понятие геймдизайна + один вопрос» (с кубиком из колоды понятий урока в lessons/urok-01.js); ученик видит отзыв у себя на шаге.
6. Добавь в lessons/urok-01.js чекпоинт «Играем вместе» между «Мастерской» и «Открытием»: шаг arcade (побей рекорд соседа), шаг playtest (отзыв на игру соседа), шаг text с итогом «доминирующая стратегия».
7. Личная аркада ученика: мои игры по урокам, достижения пока не нужны.

Правила: Node.js 18+ без зависимостей, стиль кода и интерфейса — как в срезе 1 (public/style.css, Lab.el), всё по-русски, все вопросы — кнопками и мини-играми, геймпад там, где есть игра. Данные — только в portal/data/ через lib/store.js. Игры учеников — только в рамке sandbox с CSP sandbox.

Проверка: расширь portal/tools/e2e-portal.js — два ученика в одном классе собирают игры (подставной ИИ), играют в игры друг друга, бьют рекорд, оставляют плейтест, учитель пишет отзыв. Должны проходить: node portal/tools/e2e-portal.js и node portal/tools/check-game.js --self. Посмотри снимки экрана в portal/.check/ и поправь вёрстку, если что-то выглядит плохо.

В конце: обнови portal/README.md (типы шагов, срез 2 готов), docs/01_Журнал_курса.md (статус этапа 3: срез 2 готов; новые решения), закоммить и отправь в main (bash .claude/hooks/autocommit.sh или git push origin HEAD:main). Сообщения коммитов — по-русски. Ключи и config.json не коммить. В ответе коротко: что сделано, как проверить у себя (node portal/server.js), что осталось.
```

## 2. Срез 3 портала: панель учителя и интерактивы (готов 17.10.2026)

```text
Ты — разработчик портала курса геймдизайна «Лаборатория игр» (репозиторий mentalart/GameLab). Сначала прочитай CLAUDE.md, docs/01_Журнал_курса.md, portal/README.md, потом код portal/server.js, portal/public/teacher.js, portal/public/student.js. Срезы 1 и 2 готовы.

Задача — срез 3:
1. Панель учителя для живого урока: режим проектора (крупно код класса, открытый чекпоинт, таймер чекпоинта по minutes из урока, сколько учеников закончили шаг); по каждому ученику — шаг, где он сейчас, сколько полей оставлено кубику (подсветка, если 3+), ошибки игры, запросы к ИИ; фильтр «застряли» (нет движения 5+ минут).
2. Вау-старт урока 1 уже готов (вкладка «Вау-старт», шаги `cards`, `play` с `shared`, `secret`). Добавь в режим проектора крупные карты и статус сборки общей игры без блока секрета.
3. Новый тип шага `rounds` — квиз «Игра или не игра?»: карточка, два ответа ◀ ▶ (клавиши, геймпад, тап), таймер, серия, звук, разбор после каждой карты, итог «Скопировать результат». Пригодится уроку 2.
4. Журнал генераций как отчёт проверки главного допущения: для каждой модели — доля игр, заработавших с первой попытки (сборка без починки и без ошибки в рамке), среднее число починок, среднее время и рубли на одну игру; выгрузка CSV. Сравнение моделей на одном и том же замысле: учитель может пересобрать замысел ученика другой моделью и открыть обе версии.
5. Лимиты: потолок рублей на урок класса и запросов на ученика уже есть в config.json — покажи их расход в панели и дай учителю добавить ученику запросов.
6. Заметки автора: статус заметки (новая / в работе / сделано), выгрузка в Markdown.

Правила: Node.js 18+ без зависимостей, стиль — как в срезах 1–2, всё по-русски, интерактив — кнопками и мини-играми. Проверка: расширь portal/tools/e2e-portal.js, должны проходить e2e-portal.js и check-game.js --self; посмотри снимки в portal/.check/. В конце обнови portal/README.md и журнал (этап 3 готов), закоммить и отправь в main. Ключи и config.json не коммить.
```

## 3. Прохождение урока N (Claude — учитель, вы — ученик)

Перед чатом запустите портал у себя (`node portal/server.js`). Создайте в панели учителя класс «Прохождение автора». Ученика откройте в окне инкогнито. Ключ ИИ впишите в `portal/config.json`, если хотите настоящие игры; без ключа урок идёт в демо-режиме.

```text
Ты — учитель курса геймдизайна «Лаборатория игр», я — ученик 14–17 лет и одновременно автор курса. Репозиторий mentalart/GameLab: прочитай CLAUDE.md, docs/01_Журнал_курса.md (стандарты, шаблон паспорта), занятие N в docs/02_Программа_курса.md и сценарий portal/lessons/urok-0N.js.

Урок идёт через портал, который запущен у меня; игры пишет ИИ портала. Ты ведёшь урок в чате как живой учитель: говоришь, какой чекпоинт я открываю в панели учителя, коротко ставишь задачу, комментируешь мои результаты (я присылаю их кнопкой «Скопировать результат»), задаёшь вопрос «Что почувствует игрок?», на плейтесте даёшь отзыв с одним понятием геймдизайна и одним вопросом. Темп — как в классе: не больше 3–4 абзацев за раз, без лекций.

Параллельно отмечай всё, что в уроке или портале нужно поправить (я тоже пишу «Заметки автора» в портале и пришлю их в конце).

В конце урока:
1. Составь паспорт урока по шаблону журнала: docs/Паспорта/Урок_0N.md.
2. Запиши итоги в docs/01_Журнал_курса.md: статус урока, открытия, решения.
3. Каждую правку оформи задачей GitHub с меткой «урок-0N» (если создать задачи нельзя — список задач в конце паспорта).
4. Закоммить и отправь в main.

Начинаем урок N. Скажи, какой чекпоинт мне открыть первым.
```

## 5. Сборка урока N (до прохождения)

```text
Ты — разработчик портала курса «Лаборатория игр» (репозиторий mentalart/GameLab). Прочитай CLAUDE.md, docs/01_Журнал_курса.md, занятие N в docs/02_Программа_курса.md (донор, вау-момент, секрет, своя игра на трёх уровнях, играем вместе, линза), portal/engine/README.md (контракт игры), portal/README.md (типы шагов) и как образец — portal/lessons/urok-01.js и portal/games/nlo-v-stanice.js.

Собери урок N:
1. Ремейк-донор учителя в portal/games/<имя>.js по контракту GAME: своё название и мир (Адыгея или из колоды миров), подпись донора, яркая лоуполи 3D, геймпад, ручки со всеми важными числами, секрет донора — отдельной ручкой и пресетом «Без секрета», «Новичок», честное предупреждение («видно = правда»), телеметрия под понятие урока в overNote. Проверь: node portal/tools/check-game.js games/<имя>.js — без ошибок, не больше 250 вызовов отрисовки; посмотри снимки в portal/.check/ и доведи вид до уровня образца.
2. Сценарий portal/lessons/urok-0N.js: чекпоинты по устройству занятия (Донор → Секрет → Фабрика → ИГРА и продюсер → Сборка → Мастерская → Играем вместе → Открытие), колоды кубиков под донора (чтобы кубик не приносил правило из другой игры), квиз-мини-игра урока, три уровня задания, шаблоны черновика ИГРА под донора. Если нужен новый тип интерактива — сделай его типом шага в portal/public/student.js и опиши в portal/README.md.
3. Если ремейк хороший образец механики для ИИ — сделай его образцом урока: поле sample { file, about } в сценарии (программист получает первый образец и образец своего урока, подстановка — portal/tools/build-prompt.js). Проверь: node portal/tools/build-prompt.js --sizes — промпт с каждым образцом не больше 30 тысяч токенов.
4. Расширь portal/tools/e2e-portal.js так, чтобы он проходил и урок N; должны проходить e2e-portal.js и check-game.js --self.
5. Обнови таблицу ремейков в portal/README.md и статус в журнале. Закоммить и отправь в main.
```

## 6. Хостинг (этап 5, после модуля 1)

```text
Ты — разработчик портала «Лаборатория игр» (репозиторий mentalart/GameLab). Прочитай CLAUDE.md, docs/01_Журнал_курса.md, portal/README.md (раздел «Безопасность»). Нужно подготовить пробный выезд портала на VPS в России (у учеников персональные данные несовершеннолетних, хранение — в РФ).

Сделай:
Сервер уже выбран по docs/04_Хостинг_выбор_тарифа.md: провайдер <Selectel или Timeweb Cloud>, <vCPU, память, диск, Ubuntu>, IP <адрес>, домен <домен> (паролей в чат не давать).
1. Инструкцию docs/05_Хостинг_установка.md для автора курса, по шагам, без предположения, что он админ: выбор VPS (российский провайдер, Ubuntu LTS, 2 ГБ памяти хватит), домен, установка Node.js LTS, запуск портала как службы systemd, HTTPS через Caddy, резервное копирование portal/data/ раз в день, обновление из GitHub одной командой.
2. Отдельный домен (или поддомен) для игр учеников: /play/ и /engine/ отдаются с play.<домен>, портал — с основного; в портале — настройка playOrigin в config.json, рамки и postMessage работают между доменами. Проверь локально с двумя адресами (localhost и 127.0.0.1).
3. Защиту: ограничение частоты запросов на вход и к ИИ, срок жизни сессий, пароль учителя не по умолчанию, заголовки безопасности для страниц портала.
4. Скрипты в portal/deploy/ (Caddyfile, unit-файл systemd, скрипт обновления), без секретов в репозитории.
Проверка: e2e-portal.js и check-game.js --self проходят. Закоммить и отправь в main.
```
